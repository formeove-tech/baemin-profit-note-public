# v6 — 독립 검토자(별도 세션, 대화 내용 모름) 재검토와 반영 (2026-09-21)

배포 사이트를 GPT에 줬던 것과 같은 지시로, 이 프로젝트 대화를 전혀 모르는 별도 검토자가 직접 눌러 보고 평가했다.
아래는 지적을 코드로 대조한 결과다. 계산 검산(6,700×2,000, +500원 시 +900,000·+125,000, 본전 1,398건 등)은 전부 일치했다.

## 맞았고 고친 것

| 지적 | 확인 | 반영 |
|---|---|---|
| '본사 가격'을 체크해야 더 큰 제안(할인 줄이기 +1,000,000)이 나타남 — '숨긴 추천 공개'처럼 동작 | 맞음 | 할인·포장비·옵션 제안은 항상 표시, 체크는 가격 인상 항목만 뺌 |
| 예시 B: "5% 줄면 −151,168원"인데 첫 추천 | 맞음 | 5% 감소가 손해면 제목에 '(신중)', 정렬은 둘 중 작은 값으로 → 아래로 내려감 |
| +300원: 표는 5% 감소가 손해인데 결론은 "괜찮아요" | 맞음 | 여유가 5% 미만이면 "빠듯해요. … 그보다 더 줄면 손해예요." |
| 필요한 매출 3,123,288원 (164.4건 기준) | 맞음 | 정수 주문 수(165건) 기준 금액으로 |
| 주문 금액 합계 4,000만 vs 표의 할인 뺀 매출 3,800만 | 맞음 | 주문 금액 합계 칸 아래 '할인 뺀 매출 38,000,000원' |
| 예시인데 "그 날짜로 자료를 더 가져와 주세요" | 맞음 | 예시에서는 "예시 자료는 30일치만 있어요" |
| "배달비가 가장 커요" — 그래서 뭘 하라는지 없음 | 맞음 | "배달비는 배민 배달 방식에 따라 정해져요 — 줄일 수 있는 건 할인·포장비·재료비" |
| 처음 설정: 인건비는 '한 달'인데 전체 매출은 '이 기간(90일)' | 맞음 (같은 날 넣은 기능의 실수) | 한 달 전체 매출을 묻고, 배민 한 달 평균(선택 기간 ÷ 일수 × 30)과 비교 |
| 공통비·배분·정액·사업자 용어 | 맞음 | 인건비·월세 배민 몫 / 배민 몫으로 넣기 / 이 가게 |
| 본문 14px | 맞음 (text-sm) | text-sm 14 → 15px |
| "올린 금액에서 배민이 떼가는 몫 10%" 근거 없음 | 맞음 | "중개 수수료 + 결제 수수료를 어림한 값 (보통 10% 안팎)" |
| 치킨: 용기가 본사 지정 | 맞음 | "용기가 본사 지정이면 건너뛰세요" |

## 맞지만 미룬 것

- 간단히 보기를 큰 숫자 2개 + 눈여겨볼 것만으로 줄이기 — 가상 사장님 QA에서 돈 흐름의 "배달비 1건당 2,450원"이 수락 신호였어서 그대로 둠. 실제 사장님 반응을 본 뒤 결정.
- "−9원" 줄, 월별 6,703 vs 6,698 — 칩·설명으로 커버됨. 잔돈 반올림은 '반올림한 값을 다시 합산하지 않는다' 원칙과 부딪혀 보류.
- 칩(뱃지) 개수 줄이기 — '세금 떼기 전'·'인건비·월세 빼기 전' 같은 조건은 GPT 1차 검토에서 "조건을 놓친다"고 해서 키운 것이라 상충. 보류.
- 카페·분식 예시 객단가 — 예시 가게를 업종별로 늘리는 건 별도 작업.
- 원가율 기준(판매가/할인 뺀 금액) 선택 접기 — 처음 설정에서는 이미 안 보이고 '자세히 보기'에만 있음.
