## 1 제품의 목적

배달의민족에서 판매하는 메뉴와 옵션을 점검하고, 주문·정산·광고·원가 자료를 연결해 사장이 실제로 얼마를 남기는지 이해하고 개선할 수 있는 도구를 만든다. 모든 주요 결과는 금액과 비율을 함께 보여준다.

사장이 이 서비스에서 해결할 질문은 다음과 같다.

1. 평균 한 건을 팔면 할인, 수수료, 광고비, 배달비, 재료비와 포장비를 빼고 얼마가 남는가.
2. 배민에 직접 발생한 비용과 배민에 배분한 인건비·임차료까지 빼면 얼마가 남으며, 어느 비용이 이익을 줄이는가.
3. 특정 메뉴를 500원 또는 1,000원 올리면 주문당·월간 이익은 얼마나 달라지는가.
4. 가격을 올린 뒤 주문이 줄어도 기존 이익을 유지할 수 있는 한계는 어디인가.
5. 어떤 메뉴 이름, 추가 옵션, 세트 구성이 객단가와 총이익을 함께 높일 가능성이 있는가.
6. 하루 몇 건, 월 얼마를 팔아야 손익분기점과 목표 이익에 도달하는가.

제품의 우선순위는 계산의 추적 가능성, 자료 입력의 편의성, 실행할 수 있는 개선안 순이다. 실제 자료가 없을 때는 데모·추정·미확인을 명확히 구분한다.

v0.8에서는 여러 업종의 사장님이 PC와 휴대폰에서 설치 없이 웹사이트에 접속해 카카오로 가입·로그인하고 자신의 사업자를 전환해 선택한 자료를 분석한다. 누구나 가입할 수 있으며, 초기 사용성 검증은 6~20명을 대상으로 한다. 각 사용자가 배민에 별도로 직접 로그인하고 수집 버튼을 누르면 사이트가 주문·정산·광고·메뉴 자료를 자동으로 가져온다. 수집이 끝나면 해당 배민 로그인 상태를 종료하며 다음 수집에는 다시 로그인한다. 서비스 로그인과 이미 저장된 분석 자료는 유지한다. 예상 수집 빈도는 주 1~2회이며 자동 실행 일정은 아니다. 수집 자료가 검증·저장되면 AI 메뉴 개선 추천을 자동 생성하고, 손익 분석은 추천 완료를 기다리지 않고 제공한다. 전체 원가율로 분석을 시작하고 메뉴별 원가는 선택 입력한다. 첫 분석 범위는 배민 주문의 수익성이며 홀·다른 앱을 합친 매장 전체 순이익으로 표시하지 않는다. 운영자에게 다른 사장님의 매출·원가 열람 기능을 제공하지 않는다. 최근 한 달·기간 지정·3개월·6개월 분석을 제공하고 6개월을 넘는 저장 자료도 기간 지정으로 분석한다. 첫 화면에는 주문 1건당 남는 금액과 선택 기간 전체 이익을 함께 크게 보여준다. 준비 가능한 화면 캡처는 자동 수집 결과의 대조·보완 자료로 사용한다. 운영비 예산은 아직 정하지 않았으며 실제 실행량과 요금제로 비용을 산정한다.

### P1 자료 검증 후 확장

화면 캡처의 메뉴·금액 OCR 초안, 메뉴별 레시피 원가, 증빙을 활용한 부가세 조정, 메뉴 변경 전후 성과 비교를 추가한다. P0의 캡처 첨부·대조·확인 입력과 OCR 자동 읽기를 구분한다. 최초에는 사용자가 직접 로그인해 버튼을 누른 뒤 수집기가 자동으로 읽어오며, 정기 자동 수집은 후속 확장이다. 로그인 후 자동 수집은 P0에 포함한다.

### 후속 범위

유료 구독 결제, 쿠팡이츠·요기요 연동, POS 자동 연동, 홀을 합친 전체 매장 손익, 무인 정기 수집, 광고 예산 자동 변경, 배민 메뉴·가격 자동 변경은 초기 범위에 포함하지 않는다. 여러 사장님의 개별 계정은 초기 필수다. 사용자 PC 프로그램·확장 프로그램 설치, 개발자 도구에서 스크립트 실행, 운영자 실적 열람, 사장 간 공유·순위·비교는 선택된 범위에서 제외한다.

## 4 처음 사용하는 흐름

1. PC 또는 휴대폰 웹사이트에서 ‘카카오로 시작하기’를 누른다. 최초 인증 시 본인 서비스 계정과 빈 자료 공간을 생성하고 재방문 시 기존 계정으로 로그인한다. 초대 코드나 운영자 가입 승인을 요구하지 않는다. 카카오 서비스 로그인과 배민 수집 로그인은 별개다.
2. 본인 사업자를 추가하거나 기존 사업자를 선택하고 ‘배민 연결’을 누른다. 검증된 공식 인증 흐름 또는 본인 전용 원격 브라우저에서 배민에 직접 로그인한다. 필요한 인증도 본인이 처리한다. 원격 브라우저 후보는 기술 검증을 통과한 경우에 제공한다.
3. 로그인으로 접근이 확인된 배민 매장을 선택한 사업자에 연결하고 최근 한 달·기간 지정·3개월·6개월 중 기간을 선택한다. 사업자·매장·실제 시작일과 종료일을 확인한다. 한 사업자에 매장이 하나면 자동 선택하고 여러 개면 초기에는 분석할 매장 하나를 선택한다. 합산 제공 여부는 별도 결정한다.
4. 수집 버튼을 누르면 사이트가 확인된 경로에서 주문·정산·광고·메뉴 자료를 자동으로 읽어온다. 필요한 조회·페이지 이동·다운로드·서버 저장은 수집기가 처리한다. 정상 흐름에서는 사장이 엑셀을 준비하거나 결과를 복사해 붙이지 않는다.
5. 조회·다운로드 작업이 끝나면 해당 배민 인증 상태를 종료한다. 사업자·매장·기간 일치, 누락·미분류·중복·취소·환불을 검토하고 검증된 범위를 저장·계산한다. AI 추천은 저장된 자료로 자동 생성한다. 자료 결과·로그인 종료·AI 생성 상태를 각각 보여주며 수집 불가 항목은 보완 입력한다.
6. 전체 재료원가율과 포함 항목을 입력해 분석을 시작한다. 포장비를 따로 모르면 미입력으로 두되 포장비 제외 추정임을 표시한다. 메뉴별 원가는 첫 사용을 막지 않으며 나중에 선택 입력한다.
7. 배민에만 발생하는 기간 비용을 확인한다. 필요하면 인건비·월세 등 공통비의 배민 배분 금액을 입력한다.
8. 첫 화면의 두 큰 지표에서 배민 주문 한 건과 선택 기간 전체의 수익성을 함께 확인한다. AI 추천이 생성 중이어도 손익을 조회하고 메뉴·가격·옵션·세트 시나리오를 비교한다. 처음 원가를 저장하면 그 가정을 반영해 추천을 갱신한다.
9. 실행할 개선안을 저장하고 적용일을 기록한다. 사업자를 바꾸면 해당 사업자의 매장·자료로 전환한다. 다음 갱신에는 배민에 새로 로그인한 뒤 수집 버튼을 누른다. 예상 사용은 주 1~2회이며 로그인 종료 후에도 기존 자료 검토·원가 수정·시뮬레이션은 이어갈 수 있다.

‘설치 없음’은 사용자 기기에 추가 프로그램을 요구하지 않는다는 뜻이다. 원격 브라우저를 쓰는 경우 로그인은 서버의 격리된 환경에서 처리되며 수집 종료 후 재사용할 인증 상태를 남기지 않는다고 연결 화면에서 설명한다. 배민을 사용자의 다른 탭에서 열어두는 것만으로 연동이 끝났다고 안내하지 않는다. 휴대폰에서도 처음부터 결과 확인까지 진행할 수 있어야 하며 PC 사용을 필수 단계로 요구하지 않는다.

원가와 고정비를 모르면 확인된 정산 분석부터 보여준다. 미입력 비용은 0원으로 간주하지 않고, 그 비용이 필요한 이익 지표에 ‘입력 필요’ 또는 ‘일부 비용 제외 추정’을 표시한다.

## 5 자료 수집과 품질 요구사항

### DATA 01 수집 경로

공통 분석 엔진은 수집 경로와 독립시킨다. 설치 없는 로그인 후 버튼 수집, 예비 경로인 파일 업로드, 수기 입력 모두 같은 내부 데이터 형식으로 변환한다. 인증 후 제공 범위가 검증된 공식 연동이 있으면 우선 사용하고, 없거나 필요한 항목을 제공하지 않으면 격리 원격 브라우저 후보를 검증한다. 공식 연동의 존재·지원 범위·사용 자격은 아직 확인되지 않았다.

| 경로 | 구현 요구 | 확정 전 확인할 사항 |
| --- | --- | --- |
| CSV·XLSX 업로드 | 시트·인코딩·헤더 미리보기, 열 연결, 검증 결과, 가져오기 이력 | 실제 배민 파일 형식과 열 이름 |
| 수기·표 붙여넣기 | 월 합계부터 입력 가능, 필수 정보 안내 | 주문별 분석이 가능한 자료 수준 |
| 설치 없는 버튼 수집 | 초기 필수, 공식 인증 또는 본인 전용 원격 브라우저 로그인 후 조회·다운로드 | 실제 배민 로그인·조회 가능 여부, 지원 항목, 정책, 비용 |
| 화면 캡처 | P0 첨부·원본 대조·사용자 확인 입력, P1 OCR 읽기 초안 | 매장·기간·기준일, 잘림·페이지 누락·금액·옵션 누락 여부 |

공개 API나 특정 다운로드 형식이 존재한다고 가정하지 않는다. 실제 자료를 확인하기 전에는 범용 열 연결 화면과 명시적인 데모 데이터를 사용한다. 다운로드 불가능한 항목은 수기 입력으로 보완한다.

사용자가 말한 자동 크롤링은 직접 로그인하고 수집을 시작한 뒤 사이트가 읽기 작업을 수행하는 기능으로 반영한다. 공식 연동이 가능하면 같은 사용자 흐름을 제공하고, 웹 수집기를 쓰면 확인된 조회 기능에서 매장·기간 필터, 페이지 이동·더 보기, 상세 항목과 조회 종료 조건을 처리한다. 실제 로그인 화면에서 확인하지 않은 선택자·응답 필드·비공개 API 주소를 사실처럼 작성하지 않는다. 사이트에 정식 다운로드 기능이 있으면 수집기가 작업 안에서 실행·가져오기까지 처리할 수 있으며 사용자에게 로컬 파일 업로드를 필수 단계로 요구하지 않는다.

버튼 수집의 완료 기준은 실제 로그인한 계정에서 조회 가능한 범위와 필수 자료의 수집 성공으로 판단한다. 파일 업로드가 동작한다는 이유로 버튼 수집까지 완료했다고 표시하지 않는다. 필수 필드를 읽지 못하는 자료 종류는 ‘미지원’으로 표시하고 0단계에서 대안과 초기 출시 범위를 다시 정한다.

사용자는 6개월 이상 자료가 준비 가능하다고 답했지만 배민에서 그 전체 기간을 자동으로 읽을 수 있는지는 실제 검증한다. 자료 종류별 최대 조회 범위·조회 단위·가장 이른 제공일을 기록한다. 기간 지정은 6개월을 넘는 저장 자료도 분석하며, 이미 검증해 저장한 과거 자료를 최근 180일 밖이라는 이유로 분석 대상에서 버리지 않는다. 실제 제공되지 않는 과거 자료를 있다고 가정하지 않는다.

초기 장기 수집은 지원되는 조회 단위로 나누고 하위 구간별 완료·실패·원본 합계를 기록한다. 중간에 실패하면 완료된 자료는 보존하고 남은 구간을 재시도하며 겹친 거래를 중복 합산하지 않는다. 인증이 최종 종료된 뒤 다시 시작하면 새 로그인으로 남은 구간을 이어 수집한다. 이후 갱신은 필요한 새 기간과 환불·정정 재확인 기간을 수집하도록 설계해 전체 이력을 매번 무조건 다시 읽지 않는다. 과거 조회 한계는 그대로 표시하며 캡처로 일부 값을 보완해도 해당 기간의 자동 수집을 완료했다고 표시하지 않는다.

### DATA 02 로그인 수집의 경계

브라우저 수집은 조회와 다운로드로 범위를 제한한다. 비밀번호·인증번호는 사용자가 배민의 실제 로그인 화면에서 직접 입력하며 CAPTCHA나 접근 제한을 우회하지 않는다. 서비스 자체 로그인 폼으로 배민 비밀번호를 받지 않는다. 메뉴 수정, 가격 변경, 광고 결제·예산 변경을 수집 절차에 섞지 않는다.

세션 만료 시 해당 수집만 중단하고 다시 로그인하도록 안내한다. 공식 인증의 위임 토큰 또는 원격 브라우저의 배민 쿠키는 작업 실행 중에만 사용자·매장·작업 범위로 보호한다. 재무 데이터베이스와 분리한 임시 저장 영역을 사용하고, 작업이 끝나면 재사용할 인증 상태를 남기지 않는다. 원격 방식을 선택하면 인증 상태가 서버 실행 환경에 존재하므로 ‘인증 정보가 사용자 PC에만 남는다’고 표시하지 않는다. 인증 정보는 소스 코드, 로그, 분석 보고서, AI 입력, 일반 백업에 포함하지 않는다.

수집 후 인증 종료는 확정 요구다. 성공·부분 완료·실패·취소·시간 초과가 작업의 최종 상태가 되면 원격 제어 접근을 닫고 브라우저·쿠키·웹 저장소·임시 프로필 등 서비스가 보유한 인증 상태를 폐기한다. 배민이 제공하는 해당 세션 로그아웃이나 공식 토큰 철회 수단이 확인되면 함께 실행한다. 로그아웃 클릭만으로 정리가 끝났다고 판단하지 않는다. 다른 기기에 사용자가 별도로 로그인한 배민 세션까지 종료한다고 약속하지 않는다.

공식 연동 후보도 매회 사용자가 새 로그인·재인증 절차를 거치고 이전 작업의 접근·갱신 토큰을 재사용하지 않는 흐름을 지원해야 한다. 지속 인증을 필수로 요구하는 방식이라면 이 요구와 충돌함을 기록하고 초기 수집 경로로 확정하지 않는다. 배민 연결 이력·매장 식별자는 남길 수 있지만 인증 자격과 구분한다.

배민 수집 인증의 종료는 서비스 계정 로그아웃이나 분석 자료 삭제와 별개다. 비밀번호와 일회성 인증번호를 서비스 계정 정보로 저장하지 않는다. 로그인 입력과 화면은 원격 실행 환경을 거치므로 운영자나 인프라에서도 절대 처리되지 않는다는 약속을 하지 않는다.

사용자별 원격 브라우저와 수집 연결을 분리하고, 제어 화면·다운로드·작업의 접근 권한을 확인한다. 분석 서비스 계정 또는 배민 계정이 바뀌면 기존 연결과 대상 매장 일치를 재확인하고 이전 계정의 작업·세션을 재사용하지 않는다. 연결 해제 시 새 수집과 진행 작업의 추가 반영을 막고 브라우저·위임 토큰·남은 임시 인증 자료를 폐기한다.

로그인 화면 녹화, 키 입력 기록, 쿠키가 포함된 네트워크 추적은 기본 비활성화한다. 수집 오류 로그에는 단계와 오류 코드만 남기고 매출·원가·로그인 화면을 운영자에게 노출하지 않는다. 원격 제공자가 이 조건과 사용자별 접근 제어를 지원하는지도 후보 검증에 포함한다.

배민 연결을 해제해도 기존 분석 자료를 자동 삭제하지 않는다. 매장에 대한 서비스 내 소유·열람 권한이 남아 있으면 이전 자료를 볼 수 있다. 반면 서비스 내 매장 접근 권한을 철회한 사용자는 해당 매장의 기존 자료에도 접근할 수 없다.

### DATA 03 원본과 정규화

모든 수입 자료는 매장, 수집 경로, 원본 자료 식별자, 가져온 시각, 원본 행 또는 화면 항목, 분석 기간, 파서 버전과 연결한다. 원본 자료는 웹에서 추출한 조회 결과·다운로드 파일·화면 캡처·사용자 입력을 구분한다. 웹 원본 근거에는 화면 구분·적용 필터·조회 시각·재무 항목을 남기고 인증 정보와 불필요한 고객 정보를 제외한다. 열 연결 규칙은 매장·자료 유형별로 저장한다. 금액의 부호와 부가세 포함 여부를 원본별로 확인한다.

주문번호·정산명세번호·거래 식별자를 우선 사용하고, 식별자가 없으면 원본과 행의 해시를 활용한다. 같은 파일 재업로드와 다른 파일에 겹친 같은 거래 모두 중복 집계를 막는다. 수정·취소 자료는 원거래를 덮어 없애지 않고 정정 이력을 남긴다.

### DATA 04 완전성과 집계 수준

자료별 수집 시작일·종료일, 마지막 성공 시각, 행 수, 합계, 누락 기간을 표시한다. 부분 수집을 완료로 표시하지 않는다. 매장과 채널이 다른 자료의 자동 병합을 금지한다.

월 합계만 있을 때는 월 손익과 가정 기반 평균 분석을 제공한다. 주문 내역이 없으면 주문별 분포·실제 옵션 선택률·메뉴 동시구매율을 계산하지 않는다. 주문 수가 확인되지 않으면 객단가도 계산하지 않는다.

숫자의 상태는 ‘원본 확인’, ‘사용자 입력’, ‘추정’, ‘미확인’으로 구분한다. 전체 금액 중 미확인·미분류 금액의 비중도 함께 보여준다.

### DATA 05 수집 버튼과 작업 상태

수집 작업마다 사용자·사업자·매장·배민 연결·기간·자료 종류·수집기 버전을 고정해 기록한다. 시작 전 대상 사업자·매장명과 기간을 보여준다. 배민 화면의 매장이 요청한 매장과 다르면 저장을 중단한다. 서비스에서 다른 사업자를 선택하더라도 이미 시작한 작업의 대상을 바꾸지 않는다.

| 상태 | 화면 표시와 처리 |
| --- | --- |
| 로그인 필요 | 배민 로그인 후 다시 수집할 수 있도록 안내 |
| 수집 대기 | 현재 대기 상태와 선택한 매장·기간 표시 |
| 수집 중 | 주문·정산·광고·메뉴별 진행 상황, 취소 기능 |
| 검토 필요 | 미분류·필수 금액 누락·합계 차이를 표시 |
| 부분 완료 | 성공·실패한 자료 종류와 날짜 구간을 각각 표시 |
| 완료 | 확인된 자료별 기간·건수·합계와 마지막 성공 시각 표시 |
| 실패 또는 취소 | 원인과 재시도 방법, 마지막 정상 자료 보존 |

수집 중이거나 실패해도 기존 정상 데이터를 빈 값으로 덮어쓰지 않는다. 작업 중간 자료는 임시 영역에 두고 검증된 자료 종류·기간만 원자적으로 반영한다. 주문은 성공하고 광고는 실패했다면 광고가 누락된 분석임을 표시한다. 재수집 버튼을 연속으로 눌러도 같은 작업을 중복 실행·집계하지 않는다.

자료 상태와 배민 인증 종료 상태를 분리한다. 인증 상태는 ‘로그인 필요 → 로그인 중 → 수집에 사용 중 → 종료 중 → 종료 완료’로 관리하며 실패하면 ‘종료 확인 필요’를 표시한다. 자료가 저장됐어도 인증 정리를 확인하지 못했으면 ‘자료 수집 완료 · 로그인 종료 확인 중’으로 보여준다. 종료 완료 표시에는 실제 브라우저 종료·임시 자격 폐기 결과가 필요하다. 제공자 종료 요청이 실패하면 제어·수집 권한을 즉시 차단하고 서버가 정리를 재시도하며, 독립된 실행 만료시간으로 무기한 존속을 막는다. 오류 기록은 세션 식별자·단계·시각만 포함한다.

같은 작업 안의 제한된 재시도는 인증 유효기간 안에서 허용한다. 작업을 최종 종료한 후 누르는 재수집은 새 로그인부터 시작한다. 이미 저장된 자료만 검토·재계산하는 동작은 배민 로그인을 요구하지 않는다.

자료 갱신의 범위는 선택 기간이다. 늦은 환불·정정은 해당 기간을 다시 수집하면 연결되어 반영되어야 한다. 메뉴 수집값은 현재 시점의 스냅샷으로 저장하며 과거 주문의 당시 가격을 현재 메뉴가격으로 덮어쓰지 않는다.

### DATA 06 여러 사장님·사업자·매장 자료 분리

한 카카오 서비스 계정 아래 본인 자료 공간, 사업자, 배민 매장을 구분한다. 사장님은 상단에서 사업자를 전환하며 선택한 사업자의 자료를 본다. 한 사업자에 여러 배민 매장이 연결될 수 있으므로 사업자와 매장을 같은 식별자로 취급하지 않는다. 합산 방식이 정해지기 전에는 해당 사업자 안에서 매장 하나씩 분석하며 다른 사업자를 자동 합산하지 않는다. 다른 사장님의 매장·주문·원가·추천·원본·내보내기 파일은 보이지 않는다.

사업자는 내부 식별자와 표시 이름으로 관리한다. 사업자등록번호는 연결 근거가 있거나 사용자가 선택 입력한 경우에만 출처·확인 상태와 함께 기록하고 선택 화면에서는 필요한 경우 일부를 가린다. 같은 브랜드명·사업자등록번호를 입력했다는 이유만으로 사업자 소유가 검증됐다고 표시하거나 다른 계정 자료를 연결하지 않는다. 수집 시에는 로그인으로 실제 접근이 확인된 배민 매장과 사용자가 확인한 사업자 연결을 구분해 기록한다.

사업자를 바꾸면 매장 목록·원가 설정·기간 자료·추천·내보내기 범위를 함께 전환한다. 사업자 A의 원가율이나 비용을 B에 자동 적용하지 않는다. 이미 진행 중인 A의 수집·추천은 A에 고정되고, 늦게 도착한 결과가 B 화면을 덮어쓰지 않는다. 사업자 선택만으로 모든 사업자의 수집을 시작하거나 새 원격 로그인 환경을 만들지 않는다. 배민 매장의 사업자 연결을 정정할 때는 적용일·이유·기존 이력을 보존하고 과거 자료의 귀속을 조용히 이동시키지 않는다.

공개 가입은 신규 서비스 계정을 만들 수 있다는 뜻이다. 가입만으로 기존 매장·정산·원가의 접근 권한을 부여하지 않는다. 새 사용자는 빈 자료 공간에서 시작하고, 배민에 직접 로그인해 실제로 접근 가능한 매장을 확인한 뒤 본인 소유 범위에 연결한다. 같은 매장명·이메일·전화번호·외부 매장 식별자가 있다는 이유로 다른 서비스 계정의 기존 자료와 자동 병합하거나 공유하지 않는다. 초기 검증 인원 6~20명은 회원가입 제한이나 초대 명단으로 사용하지 않는다.

권한은 화면에서 메뉴를 감추는 것으로 끝내지 않는다. 서버가 로그인 사용자와 사업자·매장 접근 권한 및 두 대상의 연결을 검증하고, 수집 토큰·작업·저장 파일·캐시·보고서·AI 요청·다운로드에 같은 범위를 적용한다. 사용자가 요청 주소나 ID를 바꿔 타인 자료를 조회·수정할 수 없어야 하며 본인 사업자 A에 사업자 B의 매장 ID를 섞은 요청도 거부한다.

수집 연결 토큰은 해당 사용자와 매장, 작업 범위에 한정하고 만료·폐기할 수 있게 한다. 클라이언트가 전달한 소유자 ID를 그대로 신뢰하지 않는다. 다른 사용자 데이터의 결합이나 타 매장 평균 비교는 초기 기능으로 제공하지 않는다.

각 사장님만 자기 매장의 재무 자료를 열람한다. 운영자 계정에는 다른 매장의 매출·원가·주문·메뉴 수익 분석·추천·보고서·원본 파일·원격 로그인 화면 열람 권한을 주지 않는다. 운영자 대시보드에는 비식별 가입 수, 서비스 상태, 집계된 오류 유형 등 운영에 필요한 최소 정보만 표시한다. 컨설팅 공유, 타 계정으로 대신 로그인, 공개 보고서 링크, 타 매장 평균·순위 기능을 만들지 않는다.

일반 운영자 권한과 백엔드 처리 권한을 분리한다. 백엔드는 정해진 계산·수집 작업에만 소유 범위를 적용해 처리하며, 운영자용 API나 로그를 통해 재무 내용을 되돌려주지 않는다. 이 요구는 앱의 열람 권한을 제한하는 것으로 서버 관리자에게도 기술적으로 어떤 접근도 불가능한 종단간 암호화 서비스라는 뜻은 아니다. 사용자에게 그런 보장을 표시하려면 별도 암호화 구조와 위협 모델이 필요하다.

### DATA 07 모바일 사용과 연결 복구

휴대폰에서도 서비스 로그인, 배민 직접 로그인과 필요한 인증, 매장·기간 선택, 수집, 자료 검토, 원가 입력, 분석 조회까지 완료할 수 있어야 한다. 초기 검증 대상은 iOS Safari와 Android Chrome으로 제안하며 실제 시험 기기·운영체제·브라우저 버전을 기록한다. PC 브라우저 화면을 작게 줄인 결과만으로 모바일 수집 완료를 인정하지 않는다.

로그인 입력, 비밀번호 필드, 한글 입력·수정, 숫자 인증번호, 터치·스크롤, 화면 확대, 가상 키보드에 가려지는 버튼을 확인한다. 실제 인증 과정에서 문자 확인이나 인증 앱 이동이 필요하면 같은 휴대폰에서 복귀해 진행할 수 있어야 한다. 팝업·새 탭이 필요한 경우 그 화면으로 이동하고 되돌아오는 흐름도 검증한다. 특정 인증 방식이 휴대폰에서 끝나지 않으면 미지원 사유를 표시하고 P0 충족으로 처리하지 않는다.

인증 앱으로 잠시 이동하거나 화면을 잠갔다는 이유만으로 즉시 작업을 취소하지 않는다. 서버가 작업 상태를 관리하고, 본인 계정으로 돌아오면 기존 작업의 진행·완료 상태를 확인하게 한다. 유효한 동일 작업에만 원격 화면을 재연결하며, 만료됐거나 종료된 인증 상태는 복원하지 않는다. 일시적 네트워크 단절·새로고침 후에도 수집 요청·집계가 중복되지 않아야 한다.

수집 버튼을 누르기 전 로그인 대기는 유휴시간을 제한한다. 버튼 실행 후에는 휴대폰 화면이 닫혀도 서버 작업이 완료·실패·취소·시간 초과 중 하나로 끝나고 인증을 정리한다. 화면을 닫는 동작과 사용자가 누른 ‘수집 취소’를 구분한다. 잠정 제한은 로그인 중 10분 유휴, 원격 세션 생성부터 최대 30분이며 설정값으로 관리하고 0단계 실측으로 조정한다. 대기열에서 원격 세션이 아직 만들어지지 않은 시간은 이 제한에 포함하지 않는다. 정리 작업은 화면과 수집 작업의 생존 여부에 의존하지 않게 실행한다.

### DATA 08 실제 자료를 이용한 대조 검증

같은 기간의 주문·정산·광고 내역과 메뉴 구성, 6개월 이상 자료를 준비할 수 있으며 화면 캡처를 제공할 수 있다는 답변을 받았다. 실제 운영의 주 경로는 사이트의 자동 수집이고, 캡처는 원본 화면과 수집 결과를 대조하거나 누락 항목을 보완하는 데 사용한다. 아직 자료를 받거나 수집하지 않았으므로 실제 항목명·단위·공제 항목·조회 가능 기간을 확정하지 않는다. 수집 또는 첨부 시 매장 식별, 자료 종류, 포함 기간, 조회·촬영 시각, 메뉴 기준일, 원본 합계와 수령·검증 상태를 기록한다.

캡처에 표시된 매장·기간·필터와 전체 합계인지 일부 페이지인지 확인한다. 잘린 행·가려진 금액·여러 장의 겹친 영역·소계와 총계 중복을 점검한다. 캡처에 보이지 않는 주문·공제·기간을 추정 생성하지 않는다. 캡처에 월 합계만 있다면 그 합계 수준의 대조만 가능하며 주문별 분석이 검증됐다고 표시하지 않는다. 캡처에서 읽은 값은 사용자 확인 전 확정 원장에 반영하지 않고, 이후 OCR을 추가해도 읽기 결과와 사용자 확인 상태를 구분한다. 자동 수집된 상세 내역과 같은 기간의 캡처 합계는 대조 근거로 연결하고 두 매출·비용으로 더하지 않는다. 값이 다르면 차이와 출처를 보여주고 확인 없이 기존 정상 자료를 덮어쓰지 않는다.

| 정산 내역 | 정산 대상 주문, 모든 가산·공제 항목, 명세서 합계, 정산일·상태 | 공제 항목별 금액, 지급예정/확정액, 주문 기간과 정산 기간의 차이 |

| 메뉴 구성 | 메뉴·기본가·옵션 그룹·선택 조건·추가금·세트 수량, 화면 또는 파일의 기준일 | 실제 최소 가격, 유효한 옵션 조합, 세트 구성·가격 |

자료의 숫자를 먼저 읽어 원본 대조표를 만든 후 정규화·계산 결과와 비교한다. 프로그램이 계산한 합계를 그대로 기대값으로 복사하지 않는다. 각 차이는 원본 행·기간·분류와 연결하고 사유 없이 없애지 않는다. 표에 적은 항목이 실제 파일에 없으면 누락으로 남기고 별도 근거를 연결한다. 할인·환불·직접 결제 사례가 실제 자료에 없다면 12장과 별도 가상 사례로 검증하고 실제 사례로 검증했다고 기록하지 않는다.

현재 메뉴 화면은 촬영·추출 시점의 구성이다. 과거 메뉴 가격·옵션 구성이 별도로 없으면 현재 메뉴를 3개월·6개월 전체에 소급 적용하지 않는다. 과거 수량·판매액은 당시 주문 자료를 우선하며 메뉴 변경 이력이 부족한 분석에는 한계를 표시한다. 같은 분석 대상 기간의 주문에 대한 정산이 뒤에 발생할 수 있으므로 정산 대조에 필요한 관련 명세의 기간은 별도로 확인한다.

검증용 사본에서 고객 이름·전화번호·주소 등 불필요한 개인정보를 제외한다. 거래를 가명 처리할 때는 주문·정산·광고 사이 연결 키를 같은 방식으로 바꾸어 대조가 가능하게 한다. 실제 금액·날짜·수량은 검증에 필요한 범위에서 보존하고, 개인 자료와 공개 데모를 분리한다. 다른 참여 매장의 자료는 해당 사장님의 소유 범위에서 검증하며 이 절차로 운영자 재무 열람 기능을 추가하지 않는다.

## 6 메뉴와 옵션 점검

### MENU 01 입력 모델

메뉴명, 설명, 카테고리, 기본가격, 노출 순서, 기본 제공 구성, 인분·용량, 판매 상태, 원가, 포장비를 저장한다. 옵션은 그룹별로 연결하고 필수 여부, 최소·최대 선택 수, 기본 선택값, 추가 금액·수량·원가를 기록한다.

세트는 구성 메뉴와 수량, 대체 가능 메뉴, 추가금, 기본 제공 반찬·밥·음료를 기록한다. 메뉴와 옵션은 이름이 바뀌어도 같은 식별자를 유지하며 적용 시작일을 남긴다.

여러 업종을 지원하므로 특정 음식명이나 표준 원가율을 계산 규칙으로 고정하지 않는다. 업종은 추천 문구의 참고 정보이며 필수 입력으로 첫 분석을 막지 않는다. 1인 식사, 다인분 메뉴, 크기·용량 선택, 사이드·음료, 혼합 세트는 동일한 메뉴·옵션·구성품 모델로 표현한다. 판매 단위와 인분·수량·용량은 선택 정보로 저장하고, 3인분 한 메뉴를 주문 3건으로 세거나 크기 옵션에 기본 음식 원가를 중복 적용하지 않는다. 다른 업종의 원가율·추천·매출을 한 사장님의 근거로 가져오지 않는다.

### MENU 02 점검 항목

| 점검 | 발견할 문제 | 제안 예시 |

옵션의 최소·최대 선택 수와 금지 조합을 반영해 가능한 주문 조합만 계산한다. 조합이 많으면 최저·최고 이익 조합과 실제 많이 선택된 조합을 우선 보여준다. 판매량이 없을 때 ‘인기 없음’이라고 판단하지 않는다.

메뉴 이름 제안에서 확인되지 않은 중량, 원산지, 판매 1위, 누적 판매, 효능을 만들어 넣지 않는다. 예를 들어 ‘얼큰국밥 + 수육 구성’도 실제 판매 가능한 구성과 원가가 있을 때만 제안한다.

### MENU 03 추천 결과

각 추천은 현재 상태, 근거 기간·표본, 바꿀 내용, 금액 차이, 주문당 추가 공헌이익, 선택 기간 효과의 가정, 실행 난이도와 확인할 지표를 포함한다. 월 효과를 따로 제시하면 산정 기간·주문 수 가정을 명시한다. 판매 데이터가 없는 이름 개선안의 매출 증가율은 숫자로 단정하지 않는다. 업종 이름보다 해당 매장의 실제 판매 구성·원가·포장·조리 제약을 우선하며 업종 평균 이익률을 임의로 만들어 추천하지 않는다.

AI 추천은 자료 수집 후 자동 생성하는 P0 기능이다. 추천에는 대상 사업자·매장·기간과 자료·원가 기준을 표시한다. 생성 중에도 손익과 규칙 기반 진단을 제공하며 이전 추천은 기준일과 함께 구분한다. 중복 실행·실패·원가 변경 처리는 14.4를 따른다. 추천의 기본 정렬은 확인 가능한 총공헌이익 개선 가능성을 우선하되 숫자를 계산할 근거가 없는 이름 제안은 별도로 표시한다. 이는 임시 정렬 기준이며 추천 실행은 사용자가 결정한다.

## 7 공제 항목과 정산 원장

### LEDGER 01 항목 분류

아래 분류는 내부 분석용이다. 배민 원본의 실제 항목명과 구분은 확인 후 연결하며, 존재하지 않는 항목을 있다고 표시하지 않는다.

| --- | --- | --- |
| 중개 비용 | 적용 상품별 중개 이용료와 관련 세액 | 원본에 세액이 포함됐는지 확인 |

‘총정산 차감액’과 ‘플랫폼 이용 비용’은 별도 지표다. 정산액을 줄이는 항목에는 할인·환불·보류도 포함될 수 있으므로 총차감을 전부 플랫폼 수수료라고 부르지 않는다. 고객 부담 배달비가 매장에 귀속되지 않으면 매장 매출에 넣지 않는다.

### LEDGER 02 거래 속성

각 거래에는 원본 금액, 공급가액·세액·합계, 비용 부담자, 귀속 기간, 실제 차감·결제 시점, 연결 주문, 광고 캠페인, 고정·변동 성격, 원본 근거를 저장한다. 세금 정보가 없으면 미확인으로 보존한다.

광고비처럼 월 전체에 발생한 비용을 주문별로 보여줄 때는 배분값임을 표시한다. 주문별 배분 합계가 기간 총액과 정확히 일치해야 하며, 배분값을 다시 별도 비용으로 합산하지 않는다.

### LEDGER 03 정산 대조

정산 배치마다 원본의 정산대상 가산액 합계에서 차감액 합계를 빼서 명세서 지급예정액과 대조한다. 그 후 지급확정액과 실제 입금액을 별도로 연결한다. 입금 증빙이 없으면 ‘실입금 확인’이라고 표시하지 않는다.

주문 손익과 현금 입금은 각각 주문 발생일과 정산·입금일을 사용한다. 월말 주문이 다음 달 정산되더라도 매출이 사라지거나 두 달에 중복 반영되지 않아야 한다. 전월 주문의 환불·정정은 원주문과 연결하고 과거 기간 재계산 여부를 표시한다.

‘만나서 결제’ 등 직접 수령한 음식대금은 매출에 포함하되 배민 입금예정액에는 더하지 않는다. 별도 카드 수수료와 배달 대행비가 있으면 입력받는다.

차이가 나면 금액, 원본 행, 미분류 항목, 보류·환급·기간 차이 후보를 보여준다. 차이를 없애려고 임의의 조정 금액을 자동 생성하지 않는다.

## 8 손익 계산 규칙

### CALC 01 계산 모드와 명칭

| 모드 | 계산 기준 | 결과 명칭 |
| --- | --- | --- |
| 간편 분석 | 자료의 실제 금액과 입력 원가율·비용 사용, 세액 조정 전 | 예상 잔여액 부가세와 소득세 조정 전 |
| 정밀 손익 | 확인된 매출·원가·비용의 회계 기준과 세액 구분 반영 | 예상 영업이익 |

간편 분석 결과를 확정 순이익으로 표시하지 않는다. 부가세를 모든 매출·비용에서 일괄적으로 같은 비율로 제거하지 않는다. 과세 여부, 증빙, 공제 가능 여부 등 필요한 정보가 없으면 해당 조정을 미확정으로 둔다. 세율·공제 규칙의 자동화는 구현 시 공식 자료와 매장 조건을 별도로 검증한다.

통장 잔액, 정산 입금액, 영업이익, 세후 순이익은 서로 다른 지표다. 세금 적립금과 대출 원금 상환은 현금계획에서 다루고 영업비용으로 중복 차감하지 않는다.

초기 화면의 기본 범위는 선택한 매장의 배민 주문이다. 세후 추정은 초기 필수 기능이 아니며 배민 자료만으로 매장 전체의 확정 세금이나 순이익을 자동 산정하지 않는다. 세액 조정이 없는 결과에는 간편 모드 명칭을 계속 적용한다.

### CALC 02 기준 변수

모든 식은 같은 매장·채널·기간·금액 기준의 자료로 계산한다. 기호 G는 전액 취소를 제외하고 부분 환불을 반영한 음식·옵션·세트의 점주 할인 전 판매액이다. 플랫폼이 매장에 보전하는 고객 할인은 점주 할인으로 빼지 않으며, 이미 G에 포함된 음식대금 보전을 추가 매출로 다시 더하지 않는다.

| 변수 | 정의 |
| --- | --- |
| G | 점주 할인 전 상품 판매액 |
| D | 점주가 실제 부담하는 할인·쿠폰 금액 |
| R | 음식 순매출 G − D |
| N | 분석 기간 완료 주문 수, 전액 취소 제외, 부분 환불 주문은 1건 유지 |
| C | 재료원가, 반찬·서비스·폐기 포함 범위를 설정 |
| V | 주문량에 따라 변하는 비용, 재료·포장·변동 수수료·배달비 등 |
| F | 같은 기간의 고정비와 고정 예산 비용 |
| CM | 공헌이익 R − V |
| OP | 영업이익 CM − F, 정밀 기준을 갖춘 경우 |

음식대금과 별개로 매장에 귀속되는 배달 수입 등은 별도 매출 항목으로 추가하며 객단가에 포함 여부를 명시한다. 일회성 지원·보상은 구분해서 보여주고 반복 주문의 손익분기점에서 기본 제외한다.

### CALC 03 평균과 비율

~~~text
표시 객단가 = G / N
할인 후 객단가 = R / N
주문당 비용 = 같은 범위의 비용 합계 / N
비용률 = 비용 합계 / 선택한 매출 기준 × 100
공헌이익률 = CM / R × 100
영업이익률 = OP / R × 100
~~~

공제 분석의 기본 비율은 할인 전 판매액 G를 분모로 하고, 이익률은 음식 순매출 R을 분모로 한다. 각각 ‘할인 전 매출 대비’와 ‘할인 후 매출 대비’를 화면에 표시한다. 한 비교표에서 기준을 바꾸면 모든 행을 같은 분모로 다시 계산한다.

사용자가 정산액과 비교하고 싶으면 ‘같은 주문들의 정산액 대비 비용’도 보조 지표로 제공한다. 해당 주문들의 정산이 완료되지 않았으면 예정 기준임을 표시한다. 주문월 비용을 서로 다른 주문들이 섞인 입금월 총액으로 나누지 않는다. 정산액을 분모로 한 비율은 계약 수수료율이나 매출 대비 비용률과 다른 지표임을 표시한다.

기간 평균 수수료율은 수수료 합계 ÷ 해당 매출 합계로 계산한다. 주문별 비율을 단순 평균하지 않는다. 메뉴별 수익률도 판매 수량과 실제 판매 조합을 반영한다. 분모가 0이거나 필수 자료가 없으면 ‘계산 불가’로 표시한다.

이익률이 10%에서 12%로 바뀌면 +2%p로 표시한다. 이익금이 100만원에서 120만원이면 +20%다. 기준 이익이 0원 이하이면 증감률을 생략하거나 별도 설명하고 금액 차이를 우선 표시한다.

### CALC 04 원가 입력과 우선순위

첫 분석을 위해 메뉴별 원가 입력을 요구하지 않는다. 전체 재료원가율 한 개와 그 기준·포함 범위를 입력하면 추정 재료비를 계산한다. 포장비·고정비가 없더라도 확인 가능한 수준의 결과를 보여주고 제외 비용을 명시한다. 상세 원가 입력은 ‘정확도 높이기’에서 메뉴별로 선택할 수 있게 한다.

간편 입력의 기본 재료원가는 ‘할인 전 상품 판매액 G × 입력 원가율’이다. 사용자가 기존에 관리하는 원가율의 분모가 할인 후 매출인지, 세액 조정 전인지도 선택하게 한다. 재료원가율에 포장·반찬·서비스·폐기가 포함되어 있는지 저장한다.

상세 입력에서는 메뉴·옵션별 직접 원가를 사용한다. 세트 원가는 구성품 수량별 원가와 실제 포장 구성을 합산한다. 메뉴 직접원가 또는 세트 직접원가가 있으면 포함 구성품 비용을 이중으로 더하지 않는다.

같은 분석에서 상세 원가가 있는 메뉴에는 상세 원가를, 나머지 메뉴에만 원가율 추정을 적용한다. 원가율 추정 대상 매출에 상세 원가가 확인된 매출을 다시 포함하지 않는다. 주문 조리 후 환불한 음식의 원가는 환불 여부와 별개로 남길 수 있어야 한다.

상세 원가가 없는 메뉴의 이익 순위는 전체 원가율을 적용한 추정이며 실제 메뉴 원가가 확인된 순위와 구분한다. 새 옵션·세트의 재료비를 모르면 숫자 기반 수익 추천을 확정하지 않고 추가 원가 입력 또는 가정 범위를 요청한다. 상세 원가가 일부만 입력됐을 때 확인된 원가가 적용된 매출 비중을 표시한다.

가격 시뮬레이션에서 조리량과 재료 가격이 같으면 원가 금액을 유지한다. 원가율 추정만 있는 경우에도 기준 시점에서 계산한 원가 금액을 고정하는 것이 기본이다. 가격을 올렸다는 이유만으로 동일 음식의 재료비를 자동으로 올리지 않는다.

### CALC 05 고정비와 매장 범위

인건비, 임차료, 관리비, 전기·가스·수도, 정액 광고비, 보험·통신·프로그램비, 감가상각 등을 입력할 수 있게 한다. 고정·변동·혼합·단계형 성격과 적용 기간을 정한다. 혼합 비용은 기본요금과 사용량 비용으로 나눌 수 있게 한다.

대표자 본인의 인건비는 ‘실제 회계비용’과 ‘목표 보수 또는 기회비용’을 구분한다. 필요하면 대표자 목표 보수를 확보한 뒤의 잔여액과 목표 매출을 별도로 보여준다.

홀과 배달이 같은 직원을 사용한다면 배민에 모든 인건비를 자동 배분하지 않는다. 초기 버전은 공통비의 배민 배분 금액을 직접 입력하거나, 사용자가 입력한 전체 비용과 배분 비율로 계산한다. 매출 비중을 사용하려면 별도로 입력한 전체 매출과 기간이 맞아야 하며 배민 매출만으로 비율을 추정하지 않는다. 이 보조 입력으로 매장 전체 손익 분석 기능이 추가되는 것은 아니다.

화면에는 다음 세 수준을 구분한다. 원가가 추정치라면 각 수준에도 추정 표시를 유지한다.

| 수익성 수준 | 계산 | 고정비 입력이 없을 때 |
| --- | --- | --- |
| 배민 공헌이익 | 배민 순매출 − 주문에 따라 변하는 비용 | 변동 비용이 확인되면 표시 |
| 배민 직접비 차감 후 잔여액 | 공헌이익 − 배민 전용 기간 비용 | 전용 비용 누락 시 미확인 표시 |
| 공통비 배분 후 배민 손익 | 직접비 차감 후 잔여액 − 배민에 배분한 공통비 | 공통비 입력 필요 표시 |

예를 들어 월 광고 예산이 배민 전용 고정 비용이면 두 번째 수준에서 한 번 차감한다. 세 번째 수준에서는 이미 차감한 광고비를 다시 빼지 않는다. 배민 직접비 차감 후 잔여액과 매장 전체 순이익을 같은 값으로 표시하지 않는다.

### CALC 06 손익분기점과 목표 이익

판매 구성, 주문당 변동비와 고정비가 일정하고 CM과 R이 양수인 기본 모델에서는 다음을 사용한다.

~~~text
주문당 공헌이익 c = CM / N
손익분기 주문 수 = 올림(F / c)
손익분기 순매출 = F / (CM / R)
목표 이익 T 달성 주문 수 = 올림((F + T) / c)
일평균 필요 주문 수 = 올림(필요 주문 수 / 해당 기간 실제 영업일 수)
~~~

기간 중 휴무일을 반영하고, 월 중간 실적을 보여줄 때 발생한 고정비와 월 전체 예상 고정비를 구분한다. 이미 달성한 누적 공헌이익을 제외한 ‘남은 영업일의 하루 필요 주문 수’도 제공한다.

공헌이익이 0 이하이면 현재 구성에서는 판매 증가만으로 고정비를 회수할 수 없다고 표시한다. 수수료 구간, 배달비 구간, 인력 추가 등 비용이 단계적으로 바뀌면 단순식을 쓰지 않고 구간별 재계산으로 최소 달성 매출을 구한다. 과거 매출이 향후 수수료 구간에 영향을 주는 경우 적용일과 산정기간을 별도로 반영한다.

이 제품에서 F는 배민 전용 고정비와 배민에 배분한 공통비의 합계다. 공통비가 미입력이라면 배민 전용 비용만 회수하는 기준을 별도 표시할 수 있으나 이를 매장 전체 손익분기점이라고 부르지 않는다. 배분까지 입력하면 결과명을 ‘공통비 배분 후 배민 손익분기점’으로 한다. 같은 배분 가정은 가격 시나리오와 목표 이익 역산에도 적용한다.

### CALC 07 선택 기간과 월별 비용

기본 분석은 선택 기간에 발생한 주문의 손익이다. 정산·입금 화면은 정산일·입금일 기준임을 별도 표시한다. 3개월·6개월 결과는 해당 기간의 거래와 비용을 합산해 계산하며 최근 한 달 결과에 3 또는 6을 곱하지 않는다. 매출·비용·객단가·이익률은 같은 범위로 계산하고, 전체 이익률은 전체 이익 ÷ 전체 기준 매출이다. 월별 비율의 단순 평균을 쓰지 않는다.

일별 실제 광고비·수수료·배달비가 있으면 그 귀속일과 실제 금액을 사용한다. 월 정액비처럼 선택 기간과 일부만 겹치는 비용은 원본 적용 기간을 우선한다. 세부 발생일이 없으면 사용자에게 배분 기준을 보여주고 잠정적으로 달력 일수에 따른 일할 배분을 사용한다. 이를 확정된 일별 실비로 표시하지 않는다. 선택 기간에 대해 직접 입력한 총비용은 한 번만 반영하고 월 비용으로 다시 곱하지 않는다.

~~~text
월 정액비의 선택 기간 배분액
= 각 월의 비용 × (해당 월과 선택 기간이 겹치는 일수 / 해당 월의 실제 일수)의 합
~~~

예를 들어 2026년 8월 정액비 310,000원과 9월 정액비 600,000원이 있고, 8월 18일~9월 16일을 선택했다면 310,000 × 14/31 + 600,000 × 16/30 = 460,000원을 배분한다. 배분 결과의 반올림 잔액은 상세에 기록하고 기간 총액과 일별·월별 합계가 일치하게 처리한다. 달력 일수 배분과 영업일 기준 손익분기 주문 수를 구분한다.

여러 달에 걸친 원가율·메뉴별 원가·요율·광고비 변경은 적용일에 맞춰 반영한다. 새로 입력한 현재 원가율을 과거 6개월 전체에 자동 적용하지 않는다. 과거 원가가 없으면 사용자가 지정한 기간에 같은 원가율을 추정 적용할 수 있게 하되 가정과 영향을 받는 기간을 표시한다.

누락 기간은 매출·비용 0원으로 채우지 않는다. 수집이 완료되어 실제 거래가 없다는 근거가 있을 때만 0으로 표시한다. 자료 종류별로 요청 기간·확인된 기간·빈 구간을 보여주며 자료가 있는 부분의 합계는 ‘수집된 기간의 부분 합계’로 구분한다. 6개월 중 한 달만 확보됐으면 이를 6개월 손익으로 표시하거나 나머지 기간을 자동 추정하지 않는다.

선택 기간의 손익분기점에는 같은 기간의 고정비와 공헌이익 가정을 사용한다. 다음 달 목표를 계산하면 별도 목표 기간·영업일·예상 고정비를 입력받고 과거 3개월·6개월 비용을 다음 한 달 고정비로 가져오지 않는다. 월별 추이에는 일부만 선택된 첫 달·마지막 달을 표시한다. 증감을 비교할 때는 비교 기간과 영업일 수 차이를 보여주고 기간 길이가 다른 총액만으로 개선 효과를 단정하지 않는다.

## 9 가격 변경 시뮬레이션

### SIM 01 입력

메뉴·옵션·세트별 인상·인하 금액 또는 비율을 입력한다. +300원, +500원, +1,000원 버튼과 직접 입력을 제공한다. 기간·가격 적용일, 판매 수량·주문 수, 재료 단가, 광고 예산, 할인, 배달비, 판매 구성, 주문 감소율을 각각 조정할 수 있어야 한다.

기준 실적 기간과 시나리오 적용 기간을 구분해 저장한다. 초기 비교는 같은 기간·같은 기준 주문 집합에서 가격과 가정을 바꾼 결과로 제공한다. 3개월 실적의 추가 이익을 ‘월 추가 이익’으로 표시하지 않는다. 미래 한 달로 환산하는 경우 예상 주문 수·영업일·비용 가정을 별도로 보여준다.

주문에 같은 메뉴가 2개 들어가면 인상액도 수량만큼 반영한다. 특정 메뉴의 가격만 올리면 해당 메뉴가 포함된 주문만 재계산한다. 여러 메뉴가 들어간 주문을 메뉴별로 중복 주문 처리하지 않는다.

요율은 수수료별 과금 기준, 공급가·세액, 반올림 방식, 유효 기간, 구간 조건을 가진 규칙으로 관리한다. 과거의 평균 공제율을 가격 인상분에 그대로 곱하지 않는다. 실제 요율을 모르면 사용자가 입력한 가정 기반 결과로 표시한다.

### SIM 02 결과

현재와 변경 후 객단가, 주문당 공헌이익, 이익률, 기간 총이익, 추가 이익, 손익분기점, 기존 이익을 유지하는 최소 주문 수를 비교한다. 가격 인상률, 이익금 증가율, 이익률 변화 %p를 구분한다.

주문 유지, 5% 감소, 10% 감소, 15% 감소를 기본 비교 시나리오로 제공하되 이는 수요 예측이 아니라 사용자가 검토할 가정이다. 실제 주문 감소율을 AI가 근거 없이 확정하지 않는다.

~~~text
변경 후 기간 이익 = 변경 후 주문 수 × 변경 후 평균 공헌이익 − 변경 후 고정비
추가 이익 = 변경 후 기간 이익 − 기준 기간 이익

고정비가 같고 판매 구성이 동일하며 c0 > 0, c1 > 0인 경우
기존 이익 유지 주문 감소 한계 = 1 − c0 / c1

고정비가 달라지는 일반 경우
기존 이익 유지 최소 주문 수 = 올림((기준 이익 + 변경 후 고정비) / c1)
~~~

이 식에서 감소 한계가 음수이면 주문 감소를 허용할 여지가 없고 주문 증가가 필요하다고 설명한다. 기존 이익이 적자일 때 ‘기존 손실 유지’와 ‘손익분기 달성’을 별도로 계산한다. 단순식의 조건이 성립하지 않는 혼합 주문·구간 요금은 주문별 재계산 또는 수치 탐색을 사용한다.

### SIM 03 목표 역산

‘월 100만원 더 남기려면’, ‘주문당 500원 더 남기려면’, ‘이익률 15%를 만들려면’을 선택하면 가능한 가격·추가 판매량 후보를 계산한다. 가격 상한과 가정한 주문 감소 범위 안에서 해가 없으면 달성 불가로 표시한다. 수요 자료가 없을 때 하나의 가격을 최적 가격이라고 단정하지 않는다.

## 10 객단가 개선 추천

### GROWTH 01 옵션

고기 추가, 밥 변경, 사이드, 음료 등 실제 제공 가능한 옵션별 판매가·추가 원가·추가 포장비·추가 수수료를 계산한다. 기존 옵션 선택률과 변경 후 선택률 가정을 분리한다.

~~~text
옵션 1회 추가 공헌이익
= 옵션 추가 순매출 − 추가 재료비 − 추가 포장비 − 추가 변동 비용

단순 월 추가 공헌이익
= 적용 가능한 주문 수 × 선택률 증가분 × 옵션 1회 추가 공헌이익
~~~

이 식은 주문 수와 다른 상품 선택이 같을 때의 값이다. 기존 고마진 옵션을 대체하거나 무료 구성이 유료 옵션으로 이동하는 경우 대체된 매출·원가를 함께 반영한다. 옵션 노출 주문 수가 없으면 전체 완료 주문 대비 구매율로 표시하고 노출 전환율이라고 부르지 않는다.

### GROWTH 02 세트

1인·2인·가족·단체 등 매장에 맞는 구성을 만들되 먼저 실제 판매 메뉴, 조리 동선과 포장 제약을 확인한다. 같은 구성의 단품 합계, 세트 판매가, 고객 할인액, 점주 추가 공헌이익, 포장 변화, 기존 주문의 세트 전환 비중을 보여준다.

기존에 단품을 함께 구매하던 고객이 세트 할인만 받는 경우도 계산한다. 객단가가 올라도 총공헌이익이 줄면 상위 추천에서 제외하거나 이유를 명확히 표시한다. 두 그릇을 한 주문으로 묶는 경우 주문당 배달비를 두 번 부과하지 않는다.

### GROWTH 03 이름과 배치

메뉴명·짧은 설명·옵션 그룹명·추천 순서의 전후안을 제공한다. 이름 개선만으로 기대 매출을 계산하지 않는다. 고마진 옵션의 설명을 구체화하고, 불필요한 선택을 줄이되 고객에게 실제 구성과 최종 가격을 명확히 보여준다.

### GROWTH 04 검증과 광고

추천을 실행했다면 적용일, 변경 내용, 가격·광고 변화, 비교 기간을 기록한다. 주문당 공헌이익과 기간 총공헌이익을 주지표로 하고 객단가·주문 수·옵션 구매율을 함께 본다. 요일 구성·영업시간·할인·광고비가 다른 전후 비교는 인과 효과로 단정하지 않는다.

광고 데이터에 연결 주문·매출이 있으면 광고비 대비 매출, 주문당 광고비, 광고 전 공헌이익 대비 광고비를 표시한다. 광고 유입 매출을 전부 광고가 새로 만든 매출로 간주하지 않는다. 월 광고비를 주문 수로 나눈 값은 평균 배분값이며 미래의 주문당 변동비로 자동 사용하지 않는다.

첫 화면에는 사업자 선택기, 선택 매장과 ‘배민 주문 분석’을 고정 표시하고 ‘주문 1건당 남는 금액’과 ‘선택 기간 전체 이익’을 같은 비중의 큰 카드 두 개로 보여준다. PC에서는 나란히, 휴대폰에서는 연속된 두 카드로 배치하며 어느 하나를 별도 탭 안에 숨기지 않는다. 보조 지표와 당장 확인할 사항 3개를 그 아래에 둔다. 자료가 없으면 로그인과 수집 안내를 보여주고 데모 수치를 실제 매출처럼 표시하지 않는다. AI 추천 생성 중에는 해당 영역에만 진행 상태를 표시하고 손익 화면 전체를 대기 상태로 막지 않는다. 긴 원장은 상세 보기에서 제공한다. 모든 지표에서 계산식, 포함·제외 항목, 원본·입력 근거로 내려갈 수 있어야 한다.

두 카드는 같은 사업자·매장·기간·자료 버전·비용 범위를 사용한다. 기본 비용 범위는 배민 직접비 차감 후 잔여액이며 ‘공통비 제외’를 표시한다. 공통비 배분 후 손익을 선택하면 두 카드가 함께 바뀌고 적용 범위를 표시한다. 공통비 미입력은 0원으로 숨기지 않는다. 재료비가 원가율 추정이면 두 카드 모두 추정으로 표시하고, 포장비 등 누락 비용과 세액 조정 전 여부도 같은 기준으로 안내한다.

기간 잔여액을 P, 같은 분석 범위의 완료 주문 수를 N이라 하면 주문당 금액은 P/N이다. 각 카드에 해당 금액과 할인 후 순매출 대비 잔여액 비율을 함께 표시한다. 주문당 반올림 표시액을 다시 N배해 기간 이익을 만들지 않는다. N이 0이면 주문당 금액은 계산 불가로 보여주며, 비용이 확인된 기간 전체 손실은 별도로 표시할 수 있다. 원가·필수 비용이 미확인이라면 확정 순이익이라고 부르지 않고 포함·제외 범위에 맞는 추정 명칭을 쓴다.

12장의 가상 자료에서는 공통비 제외 시 두 카드가 6,700원과 13,400,000원, 할인 후 순매출 대비 35.3%를 표시한다. 공통비 배분 후 기준으로 바꾸면 2,200원과 4,400,000원, 11.6%를 표시한다. 한 카드에 공통비 제외 금액을, 다른 카드에 공통비 차감 금액을 섞지 않는다.

기간 선택은 요약·비용·메뉴 분석·가격 실험·보고서에서 공통으로 사용한다. 최초 진입은 최근 한 달로 제안한다. 사용자 확정 사항은 아래 네 가지 선택지이며, 어제까지 30·90·180일로 계산하는 상세 정의는 구현을 위한 잠정 설계다. 달력상 지난달·최근 3개 달 전체와 혼동하지 않도록 일수와 실제 시작·종료일을 표시한다.

| 기간 선택 | 잠정 범위 | 기본 표현 |
| --- | --- | --- |
| 최근 한 달 | 오늘의 한국 날짜 T를 기준으로 T−30일~T−1일, 양 끝 포함 | 최근 한 달 · 30일, 일별 추이 |
| 기간 지정 | 사용자가 시작일·종료일 선택, 양 끝 포함 | 지정 날짜와 총 일수, 길이에 따라 일별/월별 추이 |
| 3개월 | T−90일~T−1일, 양 끝 포함 | 최근 3개월 · 90일, 월별 추이와 일부 월 표시 |
| 6개월 | T−180일~T−1일, 양 끝 포함 | 최근 6개월 · 180일, 월별 추이와 일부 월 표시 |

예를 들어 한국 날짜 2026년 9월 17일에 최근 한 달은 8월 18일~9월 16일이다. 직접 지정에서는 오늘까지 선택할 수 있고 오늘이 포함되면 ‘오늘 진행 중’과 자료 기준 시각을 표시한다. 미래 날짜와 시작일이 종료일보다 늦은 입력은 막는다. 한국 시간의 시작일 00:00 이상·종료일 다음 날 00:00 미만으로 조회해 경계 주문을 빠뜨리거나 두 번 세지 않는다.

프리셋을 누를 때 실제 날짜 범위를 고정하며 저장한 시나리오·내보낸 보고서에는 그 날짜와 자료 버전을 보존한다. 달이 바뀌었다고 과거 보고서의 기간을 자동 변경하지 않는다. 기간 선택 자체가 새 배민 수집을 실행하지는 않는다. 저장된 자료의 범위와 누락을 먼저 보여주고 추가 수집 버튼을 제공한다. 직접 지정의 범위를 임의로 6개월로 제한하지 않되 실제 조회·보관 가능 범위와 분할 처리 제한을 안내한다.

휴대폰은 한 열 중심으로 요약을 배치하고 ‘로그인하여 수집’, ‘수집 취소’, 진행 상태를 찾기 쉽게 둔다. 숫자 상세 표는 가로 스크롤이나 항목별 펼침을 제공하며 금액·비율·분모를 생략하지 않는다. 가상 키보드가 열린 상태에서도 입력·인증·수집의 다음 버튼에 접근할 수 있어야 한다. 수집 뒤에는 ‘배민 로그인 종료 · 분석 자료 저장됨’처럼 두 상태를 설명하고, 다음 자료 갱신에 새 로그인이 필요함을 안내한다.

금액은 1,234,567원 형식, 비율은 기본 소수점 1자리로 보여주고 상세에서 2자리 이상을 확인한다. 합계는 내부 정밀값에서 계산하고 화면 반올림값을 다시 합산하지 않는다. 증감은 +100,000원 / +2.3%p처럼 단위를 명확히 한다.

시각화는 매출에서 잔여액까지의 워터폴, 비용 구성 막대, 가격·주문 감소별 이익 비교를 사용한다. 같은 금액을 부모 합계와 세부 비용으로 두 번 쌓지 않는다. 색상 외에 숫자와 문구로도 이익·손실을 구분한다.

예시 안내문은 ‘평균 배민 주문 2만원에서 직접비를 빼면 6,700원이 남습니다. 공통비를 배분하면 2,200원이며 부가세와 소득세 조정 전 추정입니다’처럼 작성한다. 개발 용어와 원장 구조는 일반 사용 화면에 노출하지 않는다.

| 정산 예상액 | 13,200원 | 66.0% | 소계, 광고비까지 정산에서 차감되는 가정 |
| 재료비 | −6,000원 | 30.0% | 변동비 |
| 포장비 | −500원 | 2.5% | 변동비 |
| 광고 외 고정비 배분 | −4,500원 | 22.5% | 월 900만원의 주문당 배분 |
| 세액 조정 전 잔여액 | 2,200원 | 11.0% | 결과 |

소계 행은 별도 지출이 아니다. 비용성 정산 공제는 5,800원으로 할인 전 판매액의 29.0%다. 점주 할인까지 포함한 판매액 대비 감소는 6,800원으로 34.0%다. 두 값을 모두 ‘배민 수수료’라고 표현하지 않는다.

### 12.2 월 기준과 손익분기점

~~~text
월 할인 전 판매액 = 20,000 × 2,000 = 40,000,000원
월 할인 후 순매출 = 19,000 × 2,000 = 38,000,000원
월 정산 예상액 = 13,200 × 2,000 = 26,400,000원
월 잔여액 = 26,400,000 − 12,000,000 − 1,000,000 − 9,000,000
           = 4,400,000원
잔여액 비율 = 4,400,000 / 38,000,000 = 약 11.58% 할인 후 매출 대비

주문당 공헌이익 = 19,000 − 1,400 − 600 − 3,000 − 200 − 6,000 − 500
                = 7,300원
월 고정비 = 광고 1,200,000 + 광고 외 9,000,000 = 10,200,000원
손익분기 주문 수 = 올림(10,200,000 / 7,300) = 1,398건
하루 필요 주문 수 = 올림(1,398 / 30) = 47건
이론적 손익분기 순매출 = 10,200,000 / (7,300 / 19,000)
                      = 약 26,547,945원
정수 주문 1,398건의 순매출 = 26,562,000원
~~~

월 광고비를 고정비로 처리하므로 주문당 600원을 공헌이익에서 차감한 뒤 고정비에서 또 빼지 않는다. 정산에서 이미 광고비가 차감됐더라도 손익 모형에서는 비용 성격에 맞게 한 번만 반영한다.

이 예시의 배민 공헌이익은 월 14,600,000원, 광고비까지 차감한 배민 직접비 후 잔여액은 월 13,400,000원 또는 주문당 6,700원이다. 배민에 배분한 공통비 9,000,000원까지 차감하면 월 4,400,000원 또는 주문당 2,200원이 남는다. 이 세 금액의 범위를 화면에서 구분한다.

### 12.3 주문당 판매액을 1,000원 올리는 경우

가정은 전체 주문의 판매액이 1,000원씩 증가하고 점주 할인은 1,000원으로 유지되는 것이다. 중개·결제 비용의 합계만 할인 전 판매액의 10%로 증가하고, 재료·포장·배달·기타 주문당 비용과 월 광고 예산은 같다.

~~~text
추가 순매출 = 1,000원
추가 중개·결제 비용 = 100원
주문당 추가 공헌이익 = 900원
변경 후 주문당 공헌이익 = 8,200원
~~~

| 주문 변화 가정 | 월 주문 수 | 월 순매출 | 세액 조정 전 월 잔여액 | 기존 대비 |
| --- | ---: | ---: | ---: | ---: |
| 유지 | 2,000건 | 40,000,000원 | 6,200,000원 | +1,800,000원 |
| 5% 감소 | 1,900건 | 38,000,000원 | 5,380,000원 | +980,000원 |
| 10% 감소 | 1,800건 | 36,000,000원 | 4,560,000원 | +160,000원 |
| 15% 감소 | 1,700건 | 34,000,000원 | 3,740,000원 | −660,000원 |

주문 유지 시 잔여액 비율은 순매출 대비 약 11.58%에서 15.50%로 바뀌어 약 +3.92%p다. 기존 월 잔여액을 유지하는 주문 감소 한계는 이론적으로 약 10.98%이며, 정수 주문 기준 최소 1,781건이 필요하다. 이는 해당 가정의 계산 결과이며 가격을 올렸을 때 실제 주문이 얼마나 줄지에 대한 예측이 아니다.

## 14 구현 방향

여러 사장님이 각자 사용하는 조건에 맞춰 사장별 계정이 있는 웹 서비스, 서버 데이터베이스, 서버 측 매장 권한 검사를 초기 설계에 포함한다. TypeScript 화면·서버와 PostgreSQL 계열 저장소를 설계 후보로 두며 배포 업체는 아직 확정하지 않는다. 프레임워크·라이브러리 버전은 개발 시 공식 문서와 실행 환경을 확인하고 고정한다.

### 14.0 카카오 회원 로그인과 공개 가입

서비스 회원 인증은 카카오 로그인으로 구현한다. 공식 문서에서 카카오디벨로퍼스 앱, 카카오 로그인 사용 설정, 리다이렉트 URI 등록이 필요한 점을 확인했다. REST 방식은 서버에서 인가 코드를 교환하는 흐름을 기본 후보로 삼고, 실제 앱의 키·클라이언트 시크릿 설정과 현재 규격을 확인한다. 키가 새로 발급되면 클라이언트 시크릿이 기본 설정되는 현재 안내를 따라 서버 설정에 반영한다. [카카오 로그인 개요](https://developers.kakao.com/docs/ko/kakaologin/common), [공식 설정 안내](https://developers.kakao.com/docs/ko/kakaologin/prerequisite)

서비스의 설계 요구는 다음과 같다. 로그인 요청마다 만료되는 일회성 state를 생성해 응답과 대조하고 서버가 인가 코드·토큰과 해당 앱을 검증한다. 서버에서 확인한 카카오 회원 식별자를 내부 사용자에 연결하며 브라우저가 보내는 임의의 사용자 ID로 로그인시키지 않는다. 같은 인증의 재전송·중복 요청에서도 사용자와 자료 공간이 한 번만 만들어져야 한다. 동의 취소·만료된 코드·잘못된 state는 로그인 실패로 처리한다. 이는 공식 인가·토큰·회원 정보 흐름에 더한 서비스 구현 기준이다. [카카오 로그인 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api)

카카오 앱과 회원 식별자의 조합을 고유 키로 사용한다. 외부 회원번호는 수신 시점부터 문자열 또는 정밀도를 보존하는 64비트 처리 경로로 관리해 JavaScript 숫자 변환으로 서로 다른 회원번호가 같아지지 않게 한다. 이메일·닉네임·프로필 사진은 계정 식별 키로 사용하지 않는다. 초기 분석에 불필요한 카카오 정보는 요청하지 않고 이메일 미제공이나 선택 프로필 동의 거부만으로 가입을 막지 않는다. 이 정책은 카카오 동의 화면에 표시되는 실제 항목과 일치시킨다.

로그인 성공 후에는 자체 서비스 세션을 발급한다. 세션 쿠키는 서버가 검증하고 운영 환경에서 Secure·HttpOnly 등 적절한 보호 설정을 적용한다. 카카오 비밀번호를 서비스 폼으로 받지 않으며 시크릿과 인증 토큰은 화면·일반 로그·AI 입력에 노출하지 않는다. 카카오 API 자격과 서비스 세션은 배민 수집 자격과 다른 수명으로 관리한다. 배민 수집 후 인증 종료는 카카오 서비스 세션을 종료하는 동작이 아니다. 서비스에서 명시적으로 로그아웃하면 해당 서비스 세션과 진행 중 원격 제어 접근을 철회한다.

누구나 카카오 인증 후 가입할 수 있게 구현하며 이메일 가입·초대 코드·가입 승인 절차를 초기 필수로 추가하지 않는다. PC와 실제 iOS Safari·Android Chrome에서 카카오 인증 후 사이트로 복귀하는 흐름을 검증한다. 카카오톡 앱이 없는 환경에서도 지원되는 웹 인증 경로를 확인하고 추가 설치를 필수로 요구하지 않는다. 개발팀 계정만 성공한 결과를 공개 가입 검증으로 대신하지 않으며 팀 외부의 일반 카카오 계정으로도 확인한다. 실제 앱 설정과 선택한 동의 항목의 사용 조건을 확인하기 전에는 공개 가입이 이미 동작한다고 표시하지 않는다.

### 14.1 설치 없는 수집 경로

일반 웹페이지가 다른 출처의 문서·로그인 상태에 임의로 접근하는 것은 브라우저의 동일 출처 정책에 의해 제한된다. 따라서 자체 사이트에서 배민 탭을 열거나 배민 주소를 iframe에 넣는 것만으로 주문·정산을 읽어오는 설계를 하지 않는다. [MDN 동일 출처 정책](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)

공식적으로 지원되는 연동이 있는지, 사용 자격을 확보할 수 있는지, 메뉴·옵션·주문·정산·광고의 필요한 항목을 제공하는지 먼저 확인한다. 휴대폰 인증과 수집 후 자격 폐기·다음 수집 재인증도 선택 조건이다. 가능한 인증·토큰·동의 화면은 확인된 공식 규격을 따른다. 공개 API나 OAuth 지원이 있다고 가정해 주소·범위를 만들어 넣지 않는다.

| 경로 | 설치 없는 사용자 흐름 | 선택 조건 |
| --- | --- | --- |
| 공식 서버 연동 | PC·휴대폰에서 공식 인증·매장 연결 후 수집, 종료 후 인증 자격 폐기 | 지원 항목·이용 자격·인증 방식과 매회 재인증을 실제 확인한 경우 |
| 사용자별 격리 원격 브라우저 | PC·휴대폰에서 본인 전용 화면으로 배민 직접 로그인 후 수집, 종료 후 실행 환경 폐기 | 양쪽 기기의 실제 로그인·조회·다운로드·인증 종료와 운영 조건을 충족한 경우 |
| 예비 파일 업로드 | 사용자가 배민에서 받은 파일을 웹사이트에 올림 | 수집 장애 시 보완 수단, 버튼 수집 완료로 대체하지 않음 |

원격 브라우저는 서버에서 실행되는 브라우저의 화면을 사용자가 웹에서 조작하는 방식이다. Browserbase 문서는 실시간 화면을 웹에 넣는 기능과 모바일 화면 크기 설정을 설명하지만, 모바일 키보드는 공식 지원되지 않아 별도 입력 전달 처리가 필요하다고 안내한다. 따라서 모바일 화면 표시만으로 실제 로그인 가능성을 인정하지 않는다. 이는 후보 기술의 제약을 확인한 것이며 이 제공자를 선정하거나 배민 동작을 확인한 것은 아니다. [Browserbase 공식 실시간 화면 문서](https://docs.browserbase.com/platform/browser/observability/session-live-view)

0단계에서 실제 iOS·Android 휴대폰으로 DATA 07의 입력·인증 전환·수집·종료까지 검증한다. 입력 중계가 필요하면 본인의 실제 원격 배민 화면을 조작하는 채널로만 사용하고 비밀번호를 받는 별도 서비스 로그인 폼이나 자격 저장 기능을 만들지 않는다. 한글 조합·삭제, 특수문자·인증번호 입력을 포함해 검증한다. 모바일에서 이 경로를 완성하지 못하면 PC 성공만으로 수집 경로를 확정하지 않는다.

원격 브라우저를 검증할 때는 사장별로 격리된 실행 환경을 생성하고 소유자가 로그인 화면을 조작하게 한다. 로그인 후 사용자가 수집 버튼을 누르면 정해진 조회·다운로드만 수행한다. 사용자 PC의 기존 배민 쿠키를 복사하거나 붙여 넣게 하지 않는다. 로그인 중에는 자동 수집을 멈추고 로그인 후에는 조회 작업으로 제어를 전환한다.

원격 제어 화면과 스트림에도 서비스 로그인 사용자·세션 소유권 검사를 적용한다. 단순히 외부 제공자의 제어 URL을 공개하거나 주소를 알면 누구나 볼 수 있게 두지 않는다. 제어권·파일 다운로드·재접속에 만료와 철회를 적용하고, 제공자의 접근 제어로 충족되지 않으면 소유권을 검증하는 중계 구성을 마련한다. 충족할 수 없는 제공자는 후보에서 제외한다.

원격 수집기를 Playwright 등으로 구현하는 경우 인증 상태에는 계정을 대신 사용할 수 있는 쿠키 등이 포함될 수 있다. 이를 일반 보고서·원장·오류 로그·소스 저장소와 분리하고 필요한 실행 작업에만 접근을 허용한다. [Playwright 공식 인증 문서](https://playwright.dev/docs/auth)

작업이 최종 종료되면 브라우저 실행과 임시 인증 상태를 정리하고 다음 작업에 재사용하지 않는다. 다운로드한 자료의 서버 수신을 확인하면 로그인 상태 없이 정규화·손익 계산을 진행한다. 로그인 입력 중의 유휴 만료와 이미 시작한 수집의 실행 만료를 구분하며, 모바일 앱 전환·화면 닫힘 처리는 DATA 07을 따른다. 명시적 연결 해제나 서비스 로그아웃 시에는 해당 제어 채널과 진행 작업의 추가 자료 반영을 차단하고 인증을 정리한다. 이와 달리 정상 수집 후 배민 인증만 종료할 때는 서비스 로그인과 분석 자료를 유지한다.

정리 요청과 실제 종료 확인을 분리해 기록하고, 작업 프로세스가 중단돼도 별도 정리 작업이 만료된 실행 환경을 찾아 종료하게 한다. 원격 제공자의 실행 시간 상한 또는 동등한 독립 종료 수단을 검증한다. 정리를 확인하지 못한 기존 환경은 제어·수집에 다시 쓰지 않는다. 재시도·실행 만료로도 종료를 확인하지 못하면 기술 오류를 기록하고 해당 사용자의 새 원격 실행을 제한하며 종료 미확인 상태를 숨기지 않는다.

배민 측의 접근 제한·CAPTCHA·인증 정책 때문에 진행할 수 없으면 우회하지 않고 필요한 사용자 인증 또는 수집 불가 상태로 처리한다. 버튼 수집을 검증하지 못하면 이 부분은 개발 위험으로 남는다. 사용자 설치 금지를 무시해 확장 프로그램이나 설치형 앱으로 조용히 변경하지 않는다.

### 14.2 계산과 자료 보호

코드는 화면, 자료 가져오기, 원장 정규화, 계산 엔진, 추천, 저장소, 외부 수집기로 분리한다. 계산 엔진은 AI와 네트워크 없이도 재현 가능한 함수여야 한다. 원화 원본 금액은 정수로 보존하고 요율·배분·중간 계산에는 정확한 십진 계산 또는 유리수 계산을 사용한다. 최종 반올림은 항목별 규칙을 따른다.

AI는 계산 결과를 설명하고 메뉴 이름·구성 후보를 제안하는 데 사용한다. 합계, 요율, 세액, 손익분기점 계산은 계산 엔진이 담당한다. AI가 제안한 구성을 엔진으로 다시 계산해 숫자를 검증한다. API 연결이 없어도 분석과 규칙 기반 추천은 동작하게 하되 이를 AI 자동 추천의 구현·검증 완료로 표시하지 않는다.

외부 AI에는 추천에 필요한 본인 매장의 메뉴 정보와 집계 수치만 전달한다. 고객 이름·전화번호·주소, 사업자등록번호, 인증 정보는 추천 입력에서 제외한다. 외부 전송 범위와 AI 사용 비용을 설정에서 확인할 수 있게 한다. 가져온 메뉴 설명이나 파일의 텍스트를 실행 지시로 해석하지 않는다.

원본 재무 자료와 분석 결과의 내보내기·백업·복원·삭제 기능을 소유 범위별로 제공한다. 원본 보존 대상에서 고객 연락처·주소 등 불필요한 개인정보를 제외하고 재무 값과 출처 연결은 유지한다. 매장 간 자료 격리와 서버 측 권한 검사는 필수다. 서버 비밀키나 다른 사용자의 인증 상태를 화면에 내려보내거나 저장소에 커밋하지 않는다. 수집기와 서버는 버전 호환 여부를 확인하고 맞지 않는 자료를 조용히 오해해 저장하지 않는다.

공유 링크·운영자 재무 조회·운영자 계정 대행 로그인을 구현하지 않는다. 운영자 화면과 오류 추적 도구에도 사장님의 재무 본문이 섞이지 않아야 한다. 외부 AI에 전달하는 데이터는 매장별로 분리하고 다른 매장의 응답·캐시·검색 결과를 재사용하지 않는다.

### 14.3 공개 가입, 시험 운영과 서버 비용

원격 브라우저 실행 시간, 세션 수, 재시도 횟수, 분석 호출량을 기술 운영 지표로 측정한다. 원격 브라우저 또는 AI 비용을 사장님의 음식점 원가·배민 수수료에 자동으로 섞지 않는다. 이는 서비스 운영 비용이다. 운영자에게는 재무 내용 없이 기술 사용량의 합계만 보여준다.

초기 검증 참여자는 6~20명이며 회원가입은 공개한다. 검증 인원, 전체 가입자 수, 실제 수집 사용자 수, 동시에 실행하는 원격 브라우저 수를 각각 구분한다. 한 사장님의 활성 수집은 한 번에 하나로 제한하는 것을 기본 설계로 두고 전체 실행 수는 설정으로 관리한다. 처리 한도를 넘으면 본인 작업의 대기 상태를 표시한다. 원격 실행 자리가 없는 경우 로그인 환경을 먼저 열어 장시간 방치하지 않고, 자리가 확보되면 로그인부터 진행하게 한다. 대기 중 취소와 중복 클릭을 처리하며 다른 사람의 이름·매장·작업 내용을 대기 화면에 보여주지 않는다.

개발 환경에서는 최대 20개 시험 계정의 동시 시작 요청을 수집기 모형으로 재현해 대기·분리·중복 방지를 검증한다. 실제 배민 시험은 참여 사장님이 각자 로그인하여 진행하고, 실제 성공 건수·기기·자료 범위·소요 시간을 별도로 기록한다. 20명이 동시에 배민 원격 브라우저를 사용할 수 있다고 보장하지 않으며 실행 한도는 실측과 비용에 따라 정한다.

운영비 예산은 ‘아직 미정’으로 기록한다. 이를 무료 운영만 허용하거나 비용 한도가 없다는 뜻으로 바꾸지 않는다. 초기 6~20명의 사용량으로 비용을 측정하되 공개 가입 후 전체 이용자가 그 수에 머문다고 가정하지 않는다. 수집을 하지 않는 가입자 수만으로 원격 브라우저 비용을 계산하지 않는다.

예상 이용 빈도는 주 1~2회다. 월평균 52/12주와 사장님당 한 수집 대상을 가정하면 1인당 약 4.3~8.7회, 6명은 26~52회, 20명은 약 87~173회의 수집 시작을 예상한다. 이는 월 비용이나 동시 실행 수의 보장이 아니며 실패 재시도의 실제 실행량은 별도로 측정한다. 사용자가 말한 빈도를 사업자마다 적용하는 것으로 단정하지 않고, 여러 사업자·매장을 실제로 갱신한 횟수로 모델을 보정한다. 최초 6개월 이상 수집과 이후 변경·정정 확인을 포함한 갱신의 실행 시간을 나눠 측정한다. 기존 선택 기간의 완전성을 유지할 수 있는 경우에만 증분 수집을 적용한다.

주 1~2회는 이용량 추정이며 요일 예약·무인 수집·주당 이용 횟수 제한을 뜻하지 않는다. 매번 사용자가 배민에 직접 로그인해 수집 버튼으로 시작한다. AI 비용은 변경된 자료의 자동 추천, 확정 원가 변경에 따른 갱신, 실제 재시도 호출과 사용량을 따로 측정한다. 수집 횟수와 유료 AI 호출 횟수가 항상 같다고 계산하지 않는다.

0단계 결과에는 연동 경로, 실제 지원·미지원 항목, PC·휴대폰별 로그인·수집 소요 시간, 인증 종료와 격리 결과, 화면·로그 보관 조건, 동시 실행 한도 및 대기 동작을 기록한다. 비용은 서버·DB·저장소의 기본 비용, 실제 수집 횟수와 실행 시간, AI 사용량을 후보 요금제의 포함량·과금 단위에 맞춰 산정한다. 6명·20명 시험 사용과 공개 서비스의 실제 활성 사용자 증가 시나리오를 구분하며 측정값·단가 확인일·가정을 남긴다. 주 1~2회의 예상 빈도는 사용하되 실제 실행 시간·사용량·요금제가 확인되기 전에는 구체적인 월 금액을 확정하지 않는다.

공개 서비스에서는 인증된 사용자별 중복 수집 방지, 요청 빈도 제한, 전체 작업 대기열, 실행 시간 상한을 적용한다. 한도와 대기 사유는 사용자가 이해할 문구로 보여주고 제한값은 설정으로 관리한다. 가입은 열어 두면서 실행 자원을 관리하는 것으로 초대제나 가입 승인제로 바꾸지 않는다. 가입·단순 화면 새로고침만으로 원격 브라우저를 생성하거나 외부 AI를 반복 호출하지 않는다. 같은 사용자의 같은 자료 버전·가정에 대한 재계산과 설명은 필요한 범위에서 재사용하되 다른 사용자와 재무 결과를 공유하지 않는다.

### 14.4 수집 후 AI 추천의 자동 생성

수집된 자료의 검증·정규화·저장과 해당 범위의 계산 결과가 준비되면 AI 추천을 자동 예약한다. 추가 추천 버튼을 처음부터 누를 필요가 없어야 한다. 한 수집 작업의 월별 구간·개별 페이지마다 호출하지 않고 최종 저장 범위가 확정된 뒤 시작한다. 저장 완료 기록과 추천 예약을 함께 보존해 작업 중단·이벤트 재전달에도 생성이 누락되거나 중복되지 않게 한다. AI에는 저장된 자료를 전달하며 배민 로그인 상태를 더 오래 유지하지 않는다.

자료 수집 결과, 배민 인증 정리, AI 추천 생성을 독립 상태로 관리한다. 추천 상태는 ‘자료 필요 / 대기 / 생성 중 / 완료 / 실패’로 구분하고 부분 자료·이전 자료 기준 여부를 별도 표시한다. AI가 대기·실패 상태여도 손익·정산·시뮬레이션·규칙 기반 진단을 제공한다. 규칙 기반 결과를 AI가 생성한 것으로 표시하지 않는다. API 설정 누락·장애·시간 초과는 추천 영역에 원인과 재시도 동작을 보여준다.

작업에는 소유 자료 공간·사업자·매장·시작/종료일, 정규화한 입력 내용의 해시, 원가 가정과 계산 규칙·프롬프트·모델 버전을 고정한다. 수집 시각처럼 분석 내용과 무관한 값은 해시에서 제외하고 원본 자료 버전은 추적 근거로 따로 연결한다. 같은 범위·유효 입력의 진행 중 작업은 합치고 정상 완료 결과가 있으면 재사용한다. 새로고침·중복 이벤트·변화 없는 재수집만으로 외부 AI를 다시 호출하지 않는다. 입력이 바뀌면 새 작업을 생성하며 과거 결과는 근거와 함께 보존한다. 이전 작업이 늦게 끝나도 최신 결과나 다른 사업자 화면을 덮어쓰지 않는다.

최초 수집 당시 원가가 없으면 확인된 메뉴 구성·선택 조건에 대한 정성 추천과 필요한 입력을 제공한다. 재료비를 0원으로 채우거나 수익 증가를 만들어 계산하지 않는다. 사용자가 원가·메뉴의 변경 내용을 저장하면 영향을 받는 현재 분석 범위의 추천을 새 가정으로 자동 갱신한다. 입력 중 매 글자나 가격 실험 슬라이더 이동마다 외부 AI를 호출하지 않는다. 화면 기간을 바꾸면 같은 기간의 저장 추천을 조회하고 없으면 생성되지 않은 상태를 표시하며 ‘이 기간으로 추천 생성’을 제공한다. 다른 기간 추천을 현재 기간의 결과로 표시하지 않는다.

부분 수집은 확인된 범위로 추천이 가능한지 검사한다. 가능한 경우 포함·누락 자료와 근거 기간을 명시하고 확인 가능한 추천만 생성한다. 메뉴·판매 연결 등 필수 근거가 부족하면 ‘자료 필요’로 남기고 보완 저장 후 다시 판단한다. 빈 자료나 실패한 임시 자료로 기존 정상 추천을 덮어쓰지 않는다.

자동 시도는 최초 호출 포함 최대 2회로 두고 일시적 오류에만 한 번 재시도하는 것을 초기 설정으로 제안한다. 수동 재시도도 사용자별 요청 제한과 실행 중 중복 방지를 적용한다. 작업 제한시간은 후보 모델 실측 후 설정하고 호출 횟수·입출력 사용량·실패를 기록한다. 외부 요청의 응답을 받지 못한 경우까지 과금이 정확히 한 번이라고 보장하지 않는다. 추천 숫자는 계산 엔진 결과와 대조한 뒤 표시하며 실제 배민 메뉴·가격·광고 변경은 수행하지 않는다.

| 예상 수집 빈도 | 주 1~2회 | 초기 이용량·운영비 추정에 반영, 매회 직접 로그인 유지, 자동 일정이나 이용 횟수 제한으로 해석하지 않음 |
| AI 추천 생성 시점 | 자료 수집이 끝나면 자동으로 | 검증·저장 후 자동 생성 P0, 손익 먼저 표시, 중복·부분 자료·실패·원가 변경 처리 추가 |
| 같은 사업자의 여러 매장 | 매장별로만 | 매장 하나씩 분석, 사업자 합산·중복 제거 로직은 만들지 않음 |
| AI 추천 우선순위 | 총이익 증가 | 총공헌이익 개선 가능성 순 정렬 확정, 숫자 근거 없는 이름 제안은 별도 표시 |

| 다음 작업 | 계산 엔진과 데모부터 | 배민 연결 없이 계산 엔진·데모 화면 구현, 12장·15장 기준으로 가상 검증 |

위 스물네 가지 답변을 반영했으며 이미 정한 내용을 반복해서 묻지 않는다. 17장의 선택 질문 세 가지는 모두 답변을 받아 확정했다. 예산은 금액이 정해지지 않았다는 상태를 기록한 것이다. 카카오 공개 가입·사업자 전환·자동 수집·AI 자동 추천을 포함한 핵심 PRD는 정리됐고 실제 연동 검증이 개발 첫 단계다. 화면 캡처를 모두 올려야만 설계나 수집 시제품을 진행할 수 있게 만들지 않는다. 아래 질문은 표시 범위와 추천 우선순위를 다듬기 위한 선택 사항이며 답변 전에도 확정 기능의 기술 검증을 준비할 수 있다.

1. 같은 사업자에 배민 매장이 여러 개 있으면 매장별로만 볼 것인가, 사업자 합산과 매장별을 모두 볼 것인가. 답변 전에는 매장별 분석을 기본으로 두며 서로 다른 사업자는 합산하지 않는다. 합산을 선택하면 중복 매장·매출 제거, 공통비 중복 방지와 합계 금액 기준 비율 계산을 추가한다.
2. AI 추천에서 총이익 증가, 객단가 증가, 비용 절감 중 무엇을 가장 먼저 보여줄 것인가. 모든 진단 유형을 유지하면서 표시 순서를 정하는 질문이다. 답변 전에는 근거가 있는 총공헌이익 개선을 우선한다.
3. 추천을 실제 적용한 뒤 변경 전후의 실적 비교를 초기 버전에 포함할 것인가, 초기에는 변경 내용·적용일 기록까지만 할 것인가. 답변 전에는 기록을 P0로, 자료가 쌓인 후 전후 비교를 P1로 둔다. 전후 비교를 넣어도 주문·광고·요일 변화와 함께 보여주며 인과 효과로 단정하지 않는다.

카카오 로그인·공개 가입·사업자별 전환·수집 후 AI 자동 생성은 확정 요구다. 수집은 주 1~2회 이용을 예상하되 매회 직접 로그인한 뒤 버튼으로 시작한다. 예산은 미정으로 두고 실제 비용을 산정한다. 최근 한 달과 어제까지 30·90·180일 프리셋의 상세 정의는 기존 잠정 설계를 유지한다. 실제 카카오 앱 설정, 자료별 조회 가능 기간, 배민 자동 수집과 AI 생성 실행은 아직 검증 전이다.

실제 검증은 사용자가 직접 로그인한 연결에서 주문·정산·광고·메뉴를 자동 수집해 진행한다. 화면 캡처가 있으면 같은 매장·기간·필터의 합계와 상세 항목을 대조한다. 재료원가율·포장비와 선택한 공통비 배분은 별도 입력이며 배민 화면에 없는 원가를 크롤링으로 알아낸다고 가정하지 않는다. 비밀번호나 인증번호를 문서에 받지 않고 실제 연결 시 사장이 직접 로그인한다.

첨부한 BAEMIN_PROFIT_PRD.md의 v0.8을 읽고 배달의민족 메뉴 개선과 손익 분석 서비스의 PRD와 기술 검증 계획을 완성해줘.

현재 단계의 목적은 PRD와 기술 검증 계획의 완성이다. 확정 요구사항, 임시 운영 설정, 계산 규칙, 미확인 수집 조건을 구분해줘. 필요한 운영 질문은 AskUserQuestion으로 한 번에 최대 3개만 해줘. 해당 도구를 사용할 수 없으면 같은 내용을 선택형 질문으로 보여줘. 이미 답변한 내용은 다시 묻지 말고 추가 답변 없이도 정해진 기능의 설계와 검증 계획을 완성해줘.

아직 답하지 않았다면 17장의 같은 사업자 내 여러 매장 합산 여부, AI 추천의 표시 우선순위, 추천 적용 전후 비교의 초기 포함 여부를 질문해줘. 답변 전에는 매장별 분석, 총공헌이익 개선 우선, 적용 기록 P0·전후 비교 P1을 기본으로 둬. 답변을 받으면 관련 요구사항, 데이터 모델, 완료 기준과 변경 이력을 함께 수정하고 답이 없는 부분은 임시 가정으로 남겨줘. 수동 캡처·엑셀 준비를 자동 수집 시제품의 필수 선행 조건으로 만들지 마. 유료 서비스 결제나 배포까지 실행하라는 요청으로 해석하지 마.

카카오 인증과 배민 수집 인증을 분리해줘. 카카오 공식 문서에 따라 앱·리다이렉트 URI·서버 시크릿을 설정하고, 서버가 state·인가 코드·토큰과 회원 식별자를 검증한 뒤 서비스 계정을 연결해줘. 이메일이나 닉네임을 계정 식별 키로 쓰지 말고 외부 회원번호의 정수 정밀도를 보존해줘. 최초 인증과 재로그인이 중복 계정을 만들지 않게 해줘. 카카오 비밀번호를 직접 받지 마. 일반 카카오 계정으로 누구나 가입할 수 있어야 하고 초대 코드나 가입 승인을 추가하지 마. 초기 6~20명은 시험 인원이지 가입자 상한이 아니야. 가입만으로 다른 계정의 기존 매장이나 재무 자료에 접근할 수 없게 해줘.

한 계정에서 본인 사업자를 전환할 수 있게 하고 사업자와 배민 매장을 별도 개체로 관리해줘. 사업자 선택기와 소속 매장·기간을 보여주고 원가·수집·추천·캐시·내보내기에 같은 범위를 적용해줘. 등록번호나 매장명이 같다는 이유로 다른 계정 자료를 연결하지 마. 진행 중에 사업자를 바꿔도 작업 대상은 고정하고 늦은 응답이 다른 화면을 덮어쓰지 않게 해줘. 별도 선택 전에는 같은 사업자의 매장도 하나씩 분석하며 사업자를 넘는 합산을 추가하지 마.

예산은 미정이므로 무료로 운영된다고 약속하거나 특정 금액을 확정하지 마. 주 1~2회의 예상 사용을 바탕으로 실제 수집 대상·횟수·실행 시간, AI 사용량, 저장소·서버 비용을 후보 요금제에 맞춰 산정해줘. 이 빈도를 예약 일정이나 사용 횟수 상한으로 만들지 마. 최초 장기 수집과 이후 갱신을 나누고 수집 횟수를 AI 유료 호출 횟수와 같다고 가정하지 마. 공개 가입자 수와 실제 수집 사용자 수를 구분하고 사용자별 중복 방지·요청 제한·작업 대기열·실행 시간 상한을 적용해줘. 가입이나 화면 새로고침만으로 원격 브라우저와 외부 AI 비용이 반복 발생하지 않게 해줘. 비용 때문에 초대제나 운영자 자료 열람을 도입하지 마.

AI 메뉴 개선 추천은 수집 자료를 검증·저장한 뒤 자동 생성하는 P0야. 자료 수집·배민 인증 정리·AI 생성을 별도 상태로 관리하고 손익 화면은 AI를 기다리지 않고 보여줘. 같은 사업자·매장·기간·유효 입력의 중복 호출을 막고 원가를 저장하면 영향을 받는 추천을 자동 갱신해줘. 늦게 끝난 이전 작업은 최신 결과를 덮어쓰지 않게 해줘. 원가 미입력·부분 자료에서는 확인 가능한 추천만 제시하고 이익 수치를 만들지 마. AI 장애 시 계산과 규칙 기반 진단을 유지하되 AI 완료로 표시하지 마. 14.4의 제한된 재시도·기간 구분·비용 기록을 적용하고 추천 때문에 배민 로그인 상태를 유지하지 마.

계산에서는 정산 입금과 매출을 분리하고, 모든 공제·광고·쿠폰·환불·부가세·직접 결제의 중복 집계를 막아줘. 배민 공헌이익, 배민 직접비 후 잔여액, 공통비 배분 후 배민 손익을 구분하고 홀·다른 앱을 합친 매장 전체 순이익으로 표시하지 마. 실제 요율과 API·다운로드 형식을 추측해서 확정하지 마. 원가·고정비가 없으면 순이익을 확정하지 마. 가격 변경만으로 같은 음식의 재료원가가 함께 증가하지 않게 해줘. 광고비의 주문당 평균 배분과 주문에 따라 실제 변하는 비용을 구분해줘.

가격 변경은 주문 수 유지·감소 시나리오와 기존 이익 유지 조건까지 계산하도록 해줘. 옵션과 세트는 객단가와 추가 공헌이익을 함께 비교하고, 기존 주문을 대체하는 효과도 반영해줘. 모든 주요 결과에 금액, 비율의 분모, 주문당 수치, 기간 합계, 데이터 상태를 표시해줘.

첫 화면에는 주문 1건당 남는 금액과 선택 기간 전체 이익을 같은 비중의 두 카드로 보여줘. 두 카드의 기간·비용 범위·자료 버전·추정 여부를 맞추고 주문당 금액은 기간 잔여액을 같은 기간의 완료 주문 수로 나눠 계산해줘. 원가·공통비 미입력과 세액 조정 전 여부를 숨기지 마. 공통비 제외/배분 후 기준을 바꾸면 두 카드가 함께 바뀌어야 해.

분석 기간은 최근 한 달·기간 지정·3개월·6개월을 공통으로 적용하고 기간 지정에서 6개월 초과 자료도 분석해줘. 잠정 프리셋 정의는 어제까지 30·90·180일이며 실제 날짜를 보여줘. 한국 시간의 날짜 경계, 오늘 포함 시 진행 중 표시, 일부 월 고정비 배분, 적용일별 원가·요율을 반영해줘. 장기 손익을 한 달 결과의 단순 배수로 만들거나 미수집 기간을 0원으로 채우지 마. 기간 총이익률은 합계 금액에서 계산하고 당시 메뉴 가격을 현재 메뉴로 덮어쓰지 마. 메뉴 모델을 특정 업종이나 고정 원가율에 종속시키지 마.

내가 개발 시작을 요청하면 먼저 기존 프로젝트와 실행 환경을 확인하고, 0단계의 설치 없는 로그인 후 버튼 수집 가능성부터 검증해줘. 필요한 항목을 제공하는 공식 연동과 이용 자격, 모바일 인증 및 매회 재인증 지원을 확인하고, 대안으로 사장별 격리 원격 브라우저에서 직접 로그인하는 경로를 검증해줘. 배민 API나 OAuth가 있다고 가정해 만들지 마. 일반 웹페이지가 사용자의 다른 배민 탭을 읽거나 로컬 쿠키를 자동 가져올 수 있다고 가정하지 마. 확장 프로그램·설치형 수집기·개발자 도구 스크립트·쿠키 붙여넣기를 해결책으로 넣지 마.

원격 방식을 쓰면 로그인 상태는 서버 실행 환경에 존재한다는 점을 명확히 해줘. 사장별 인증 상태·제어 화면·다운로드·작업을 분리하고, 비밀번호를 서비스 폼으로 받거나 저장하지 마. 로그인 화면 녹화와 인증 정보 로그를 기본 비활성화하고, 작업의 성공·실패·취소·만료 후 원격 브라우저와 인증 상태를 정리해줘. 다음 작업에 쿠키·프로필·토큰을 재사용하지 마. 자료 저장 성공과 인증 종료 성공을 별도로 관리하고, 종료 실패는 숨기지 말고 접근 차단·재시도·독립 만료로 처리해줘. 정상 수집 후 배민 로그인 종료는 서비스 로그인과 분석 자료를 유지하는 동작이야. 운영자 계정이 사장님의 원격 화면이나 재무 자료를 볼 수 없게 해줘. 서버의 기술적 처리까지 전혀 없다고 약속하지 마.

휴대폰 지원은 작은 화면 배치만으로 완료 처리하지 마. 실제 iOS Safari·Android Chrome에서 입력·필요 인증·앱 전환·자료 수집·연결 복구·인증 종료를 검증하고 기기·버전을 기록해줘. 원격 제공자가 모바일 키보드를 지원하는지 확인하고 실제 입력 경로를 검증해줘. 화면을 닫거나 작업 프로세스가 중단돼도 제한시간과 인증 정리가 동작해야 해. 6~20명 시험 운영을 기준으로 작업 대기열과 계정 분리를 설계하되 20개 원격 브라우저의 동시 실행이 확정됐다고 가정하지 마. 동시 요청 모형 시험과 실제 배민 수집 시험을 구분해줘.

주 경로는 사이트가 로그인 후 조회·페이지 이동·필요 다운로드·저장을 자동 처리하는 수집이야. 사용자는 화면 캡처와 6개월 이상 자료를 준비할 수 있다고 답했지만 실제 수집이나 대조는 아직 하지 않았어. 수집 결과와 캡처를 DATA 08에 따라 대조하고, 부분 화면에 없는 거래를 만들어 채우지 마. 장기 수집은 확인된 조회 단위로 나누어 성공 범위를 보존하고 실패 구간을 재시도해줘. 과거 자료의 실제 지원 범위를 확인하며 6개월 이상 준비 가능하다는 답변을 자동 크롤링 성공으로 표시하지 마. 캡처 대조·확인 입력은 P0, OCR 자동 읽기는 P1이야.

실제 연결 검증 전에는 명시적인 데모로 계정 분리와 계산 엔진을 검증할 수 있어. 전체 원가율만으로 추정 분석을 시작하고 메뉴별 원가는 선택 입력하도록 해줘. 상세 원가와 원가율을 중복 적용하지 마. 배민에 없는 재료원가·포장비를 크롤링으로 알아낸다고 가정하지 마. 파일 업로드는 예비 경로로 유지하되 사용자 파일 준비가 정상 수집 흐름의 필수 단계가 되지 않게 해줘. 12장의 예시와 15장의 핵심 테스트를 기준으로 검증하고, 설치 없는 자동 수집이 동작하지 않으면 초기 필수 기능 완료라고 표시하지 마. 실제 배민 메뉴·가격·광고 설정은 자동 변경하지 마.

단계가 끝날 때마다 무엇이 동작하는지, 어떤 자료로 검증했는지, 무엇이 미확인인지 간단히 알려줘.

## 19 확인 범위와 변경 이력

배민의 공개 진입점은 확인했으나 로그인 후 메뉴·정산 화면, 계정별 수수료, 자동 수집 허용 범위와 실제 내보내기 형식은 확인하지 않았다. 따라서 배민 관련 숫자와 데이터 열 이름은 이 문서에서 확정하지 않는다. [배민외식업광장](https://ceo.baemin.com/)

외부 문서는 Claude Code의 파일·질문 사용 방식, 일반 브라우저의 동일 출처 제약, 원격 브라우저의 일반 기능과 모바일 키보드 제약, Playwright의 인증 상태 처리, 카카오 로그인의 앱 설정·인가·토큰·회원 정보 흐름 확인에 이용했다. 실제 카카오 앱을 생성·연결하거나 일반 계정 가입을 실행한 것은 아니다. 또한 배민 공식 연동의 존재, PC·휴대폰 원격 로그인 성공과 수집 허용 여부를 확인한 것은 아니다. 메뉴 추천, 계산 엔진, 화면·권한·수집 흐름과 테스트는 이번 요청과 사용자 답변을 바탕으로 작성한 설계 제안이다. 예시 요율과 금액은 검증용 가상 값이다.
